# CLI: контракт и общие правила

Точка входа — `bin/cli.php`. Документ описывает то, что одинаково для **всех** команд.
Список команд не дублируется: источник истины — `php bin/cli.php help` (и `--json`).

## 1. Формат вызова

```
php bin/cli.php <command> [--key=value] [--flag] [--json] [--dry-run] [--verbose]
```

- аргументы — `--key=value`; флаги — `--flag`;
- неизвестные команды → exit 1 с текстом «Команда не найдена».

## 2. Результат

Каждая команда возвращает `Result`:

| Поле | Смысл |
|---|---|
| `ok` | успех команды (не путать с «ничего не изменилось») |
| `data` | машиночитаемый результат, структура зависит от команды |
| `errors[]` | причины отказа |
| `warnings[]` | предупреждения (команда выполнена) |
| `created[]` | созданные/изменённые файлы |
| `steps[]` | человекочитаемый ход выполнения |

`--json` печатает тот же объект целиком — это **единственный** формат для машинных клиентов (админка, приложение, AI).
Текстовый вывод — для человека; парсить его нельзя.

## 3. Коды выхода

| Код | Значение |
|---|---|
| `0` | `ok=true` (warnings допустимы) |
| `1` | `ok=false`, ошибка аргументов, отказ guard'а, падение |

## 4. `--dry-run`

Команды, меняющие файлы или БД, поддерживают `--dry-run`: план печатается, изменений нет.
Наличие `--dry-run` у конкретной команды — в её описании (`help <command>`).

## 5. Идентификация владельца

CLI — привилегированный интерфейс. Перед любым вызовом проверяется идентификатор:

- `var/cli.identity` (0600): `{user, created_at, secret}`;
- создаётся один раз: `php bin/cli.php cli:init --name=<кто>` — это **единственная** команда, доступная без идентификатора;
- на Unix дополнительно проверяется владелец файла (`fileowner === euid`);
- при отсутствии идентификатора любой другой вызов завершается с подсказкой.

Это учёт и точка отключения CLI, а не защита от владельца сервера: реальная граница — права ОС.

## 6. Журнал

Каждый запуск пишется в `var/log/cli/YYYY-MM-DD.log` (JSONL):

```
{"ts":"...","user":"owner","command":"page:write","args":{...},"ok":true,"errors":[],"duration_ms":42}
```

- секреты редактируются: `password`, `*pass*`, `*_b64`, `admin-sess` → `***`;
- ошибка записи в журнал **не** отменяет выполнение команды.

`cli.log` — про запуски. Изменения данных пишутся отдельно в `audit_log` (см. `data.md`).

## 7. Деструктивные операции

Единое правило: **сначала карантин, не удаление**.

- требуют `--force`;
- объект перемещается в `*_trash_<timestamp>` или в `.trash/`;
- очистка — отдельно: `trash:clear` (по умолчанию dry-run).

Типы карантина описаны в `maintenance.md`.

## 8. Guards

- **Path traversal:** имена доменов, алиасов, страниц, блоков, схем, скинов, категорий проверяются регулярками; `..` отклоняется.
- **Домен → проект:** `--domain` принимает ключ проекта или миррор; FS-пути строятся от `folder` проекта (см. `config.md`).
- **Неизвестный проект/алиас** — отказ, а не «тихий ноль».
- **Сырой PHP** пишется только при `security.allow_php_blocks=true` в `engine.config` **и** явном `--allow_php`.

## 9. Связанные документы

- `config.md` — схема `site.config`;
- `projects.md` — домены, алиасы, мирроры, сборки;
- `content.md` — страницы, блоки, филлеры, схемы, скины, языки, контент;
- `sessions.md` — AIUI-сессии;
- `data.md` — БД и провайдеры;
- `maintenance.md` — инициализация, диагностика, карантин, бэкапы.
