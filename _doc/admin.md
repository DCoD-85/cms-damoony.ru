# Руководство пользователя админки

Админка — это интерфейс управления движком для контент-менеджеров. Она работает как «тонкий клиент»: рендерит HTML и отправляет запросы в CLI (`bin/cli.php`).

⚠️ **Правило 3 файлов:** Каждая сущность (страница, блок, схема, скин) состоит из `.php` (код), `.rules.json` (настройки) и `.editor.json` (данные UI). Визуальные редакторы удалены для безопасности (защита от RCE). Редактирование кода — только через CodeMirror.

---

## 1. Вход в систему

Доступна по адресу `http://[domain]/admin/`.
- Логин и пароль хранятся в `config/admin.config`.
- **Безопасность:** После 5 неудачных попыток IP блокируется на 15 минут. Все попытки логируются в `var/admin_logs.json`. Все POST-запросы защищены CSRF.
- ⚠️ Админка использует **отдельную** авторизацию, независимую от пользователей сайта (создаваемых через `user:new`).
- В верхней панели доступен переключатель языков (RU/EN/ZH).

---

## 2. Обзор (System Health)

Главная страница показывает дерево доменов и алиасов с индикаторами состояния:
- 🟢 **Зелёный (OK)** — всё в порядке.
- 🟡 **Жёлтый (Warning)** — некритичные проблемы: отсутствует `.editor.json`, включён филлер без слота в схеме, устаревший `.rules.json`.
- 🔴 **Красный (Error)** — критичные проблемы: отсутствует `.php` файл, отсутствует корневой `algoritm.rules.json` или схема.

*(Технически данные берутся из `structure:check`)*.

---

## 3. Уровень Домена

Нажмите на домен в списке, чтобы открыть панель управления.

- **Настройки:** Заголовок, статус (Вкл/Выкл 503), выбор заглушки, время авто-включения.
- **Привязанные домены:** Управление входящими хостами (алиасами хоста). Порты и trailing-dot нормализуются.
- **Алиасы:** Список разделов (www, doc). Переключатель статуса и переход в панель алиаса.
- **Блоки (Глобальные):** Элементы шаблона (`top`, `header`). Визуального Drag&Drop нет. Редактирование через CodeMirror.
- **Схемы (Глобальные):** HTML-каркасы. Создание, копирование, удаление.
  - ✅ **Drag&Drop доступен ТОЛЬКО здесь.** Вы можете перетаскивать блоки в зоны (Визуал, Скрипты, Неактивные).
  - При сохранении структура пишется в `.editor.json`, и вызывается CLI `scheme:save` для компиляции в PHP.
- **Content:** Просмотр списка скачанных AI картинок. Только чтение. Запись и удаление — только через CLI (`content:store` / `content:remove`).

---

## 4. Уровень Алиаса

Нажмите на имя алиаса (например, `www`), чтобы перейти к его контенту.

- **Настройки:** Заголовок, статус, активный скин, разрешённые языки.
- **Страницы:** Дерево страниц (соответствует папке `algoritm/`). 
  - Корень (`/`) редактируется через кнопку «Код».
  - У каждой страницы есть переключатели Auth (🔒) и Search (🔍). Клик по ним вызывает CLI `page:toggle` и обновляет `.rules.json`. ⚠️ **Auth — метаданные**: движок не защищает; страница сама решает (см. `_doc/dev.md` §7).
  - Визуального редактора нет. Только CodeMirror.
- **Блоки (Fillers):** Переопределения глобальных блоков для конкретного алиаса.
  - Кнопка «Синхронизировать» создаёт локальные файлы.
  - Переключатель «Вкл/Выкл» вызывает `filler:toggle`. Если выключено, используется глобальный блок.
- **Схемы алиаса:** Локальные каркасы, переопределяющие глобальные.
- **Скины алиаса:** Просмотр списка скинов (`www/media/[domain]/[allias]/skin/`).
  - В админке можно только **выбрать активный скин**.
  - Создание и редактирование (стили в `css/main.css` и скрипты в `js/main.js`) — через CLI `skin:new` / `skin:edit`.
- **Content алиаса:** Просмотр файлов в `/content/[domain]/[allias]/`.

---

## 5. Глобальные разделы

- **Заглушки:** Менеджер HTML-файлов для страниц 503.
- **Безопасность:** Список активных банов (Rate Limit) с возможностью разблокировки, статистика ошибок входа.
- **Настройки:** Глобальные параметры движка (язык и т.д.).

---

## 5.1. Файловая админка (Element + dbcli + lang)

Админка построена по архитектуре домена/алиаса: `app/.admin/` — домен, `app/.admin/{role}/` — алиас роли. Точка входа — `www/admin/index.php` (строит `DomainContext` от `.admin`/`{role}` и вызывает `FrontController` с `adminRole`).
- **UI:** компоненты `Element` (Таблицы, Формы, Тоглы) с AJAX-навигацией.
- **Управление БД:** `bin/dbcli.php`. В разделе домена (`/admin/ru/domains/{domain}/db`) доступен визуальный конструктор БД. Админка вызывает `dbcli` для генерации JSON, SQL и PHP-провайдера.
- **Управление языками:** `/admin/{lang}/domains/langs` — список доменов, `/admin/{lang}/domains/langs/{domain}` — языки домена и алиасы, `/admin/{lang}/domains/langs/{domain}/{alias}` — языки алиаса. Все действия — через `lang:list`, `lang:add`, `lang:remove`, `lang:repair`.
- **Роутинг:** `FileRouter` + `FrontController` обрабатывают пути `/admin/{lang}/{role}/...`. `DomainContext` для admin — `resolve('.admin')->withAllias($role)`. Роль валидируется regex `^[a-z][a-z0-9_]*$`.

**CI/CD:** `.github/workflows/ci.yml`. PHP 8.5, `www/router.php` для эмуляции Nginx-роутинга; полный прогон — `composer test` (актуальное число тестов не документируется).

## 6. AIUI (AI-редактор страниц)

Встроенный `/admin/aiui.php` (split-screen: превью + чат). Описание — `_doc/aiui.md` (полное), `_doc/orchestrator.md` (внутренний конвейер). Модели — `config/models.config` (`ModelRouter`).

## 7. Ограничения UI (что осталось только через CLI)

Следующие операции по-прежнему **только через терминал**:

- Создание пользователей сайта (`user:new`).
- Миграции БД (`db:migrate`).
- Очистка карантина (`trash:clear`).
- Прямая запись контента в `/content/` (`content:store`; делается автоматически из `aicli.php`).
- Удаление контента (`content:remove`) и скинов (`skin:remove`).
- Создание админки новых ролей (`admin:new --role=X`).
- Прямые write-операции через AI-контекст с ролями aicli (`block:write`, `filler:write` для `brain.py`, не для AIUI).
- Низкоуровневые AI-команды: `bin/aicli.php` (роли, HATEOAS, AINET) — для `brain.py` и админа в терминале.
- Запуск мультиагента `brain.py` (Wizard) — по-прежнему только из консоли (`python -m ai_agent.brain`). **AIUI — это другой, более простой сценарий, встроенный в админку.**

---

## 8. Аварийный режим (Safe Mode)

Если конфигурация повреждена или в коде фатальная ошибка, админка не выдаст «белый экран». Вместо этого откроется красная страница с текстом ошибки (перехват `Throwable` на уровне `www/admin/index.php`).
