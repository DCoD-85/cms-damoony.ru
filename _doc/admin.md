--- НАЧАЛО ДОКУМЕНТА ---

Руководство пользователя админки
Админка — один из двух равноправных интерфейсов управления (второй — CLI). Не все операции доступны в обоих: см. MANIFEST.md §3 и §Контракты. «100% паритет CLI/UI» — неверно. Только CLI: db:migrate, vars:extract, trash:clear, user:new. Только UI: CodeMirror-редактор, визуальные редакторы блоков/схем/страниц.

⚠️ Перед началом. Визуальное сохранение затирает ручной PHP-код без предупреждения. Если страница/блок/схема правится руками — не открывайте «Визуально → Сохранить». Обратное тоже верно: если правится визуально — не трогайте PHP. См. MANIFEST.md §6.1, §7.1 п.4.

Панель управления
Доступна по адресу http://<ваш-домен>/admin/.

Вход в систему
При переходе открывается форма входа. Логин и пароль — из config/admin.config. По умолчанию: admin / secret (смените через php bin/cli.php admin:passwd).

После 5 неудачных попыток IP блокируется на 15 минут (var/admin_fails.json). Все попытки (успешные и неуспешные) пишутся в var/admin_logs.json (последние 100 записей). Разблокировка — в разделе «Безопасность» (кнопка «Разблокировать»).

Админка использует отдельную авторизацию, независимую от пользователей сайта (user:new создаёт пользователей для страниц с "auth": true, а не для админки).

Шапка, Языки, Профиль
В верхней части — тёмная навигационная панель. Справа — переключатель языков (RU / EN / ZH). Текущий выделен белым. Выбор сохраняется в cookie admin_lang. Список языков — из admin.config (domains_langs, default_lang).

Аватарка → меню:

«Мой профиль»:

Сводка (логин, роль).

Логирование (история входов с IP, очистка, отправка в архив, пагинация).

Безопасность (смена пароля с цветовым индикатором надёжности).

«Выйти».

Обзор системы (System Health)
Раздел «Обзор» показывает статус доменов и алиасов деревом.

Зелёный (OK) — всё работает.

Жёлтый (Внимание) — предупреждения (например, филлер включён, а слота в схеме нет).

Красный (Ошибка) — критические проблемы (нет файла схемы, главного контроллера страницы).

Рядом с каждым алиасом — быстрые ссылки к Страницам, Схемам, Блокам.

⚠️ StructureChecker (источник данных «Обзора») не проверяет .edit.json ↔ PHP, legacy .edit.json, blocks.json ↔ папки, schemes.json ↔ файлы. «Сироты» (пример: visuo.data.php без записи в schemes.json) не ловятся. См. MANIFEST.md §7.2 п.3. Для полной картины — проверяйте вручную.

Уровень Домена
Главная «Домены» — список реальных доменов. Нажмите на название → панель управления.

Вкладки:

Настройки: Заголовок, Статус сайта (вкл/выкл 503), Выбор заглушки, Время авто-включения, Удаление домена.

Привязанные домены: управление входящими хостами (сделать главным, отвязать, комментарии). ⚠️ При смене привязок ConfigDomainResolver не нормализует порт и trailing-dot (§6.17) — для IP-деплоя с портом используйте DNS или localhost без порта.

Алиасы: список разделов. Переключатель статуса и переход в дашборд алиаса.

Блоки (Глобальные): шаблонные элементы домена (top, left, center и т.д.). Типы: logic, ui, mixed. Создание, визуальное/кодовое редактирование.

⚠️ blocks.json (типы) записывается, но не читается RegionLoader — источник истины — папки (§4). Визуальный редактор блоков работает и данные не теряет, но перезаписывает *.php — не правьте PHP руками, если блок редактируется визуально.

⚠️ *.data.php блоков не читаются движком (§4).

Схемы (Глобальные): HTML-каркасы. Создание, копирование, удаление, визуальное/кодовое редактирование.

🔴 CSRF на destructive GET: SchemeController::delete и ::copy — GET без CSRF-токена (§7.1 п.1, P0). Не выполняйте их на публичных машинах.

🔴 Визуальный редактор схлопывает вложенные схемы в плоский div.layout (§6.15, P1). Схемы с вложенностью (например, div > main-wrap > [left, center, right]) правьте только через CodeMirror.

✅ SchemeCompiler — валидный var_export без str_replace (stage-1, §7.1 п.5 закрыт). Строки со скобками (`sm (mobile)`) сохраняются как есть.

⚠️ При сохранении схемы через UI в манифест schemes.json добавляется запись, но не проверяется соответствие файлов и манифеста. «Сироты» возможны (§7.2 п.3).

БД домена: статус базы данных. (В разработке — заглушка.)

Заглушки: HTML-файлы для 503. Создание, визуальное редактирование, удаление.

Уровень Алиаса
Нажмите на имя алиаса → дашборд.

Вкладки:

Настройки: Заголовок, Статус алиаса, Заглушка, Активный скин, Разрешённые скины и языки (чекбоксы).

Блоки (Fillers): переопределения глобальных блоков. Кнопка «Синхронизировать» создаёт локальные файлы для всех глобальных блоков. Включить/Выключить: если выключено — используется глобальный блок.

⚠️ *_<allias>.data.php филлеров не читаются движком (§4). Данные — в *_<allias>.php.

Страницы: дерево страниц в algoritm/. Создание, переключение флагов auth/search через POST+CSRF (page:toggle — правильный паттерн).

🔴 CSRF на destructive GET: BlockController::remove (кнопка «Удалить» в таблице блоков) — GET без CSRF (§7.1 п.1, P0).

✅ Форматы .edit.json: старый {blocks} и новый {slots}. `PageController::edit()` и `save()` блокируют legacy-формат с предупреждением (stage-2a). Миграция `{blocks} → {slots}` не автоматизирована — удалите файл или перепишите вручную.

⚠️ Визуальный редактор страницы (PageController::edit()) читает domains_scheme[$domain] без резолва входящего хоста. Для damoony3.ru (входящий) имя схемы не найдётся — слоты будут пустыми/дефолтными (§6.16, P1). Для визуального редактирования заходите по реальному домену.

⚠️ addslashes в PageCompiler (§7.1 п.2, P0) — контент с ', \, $, \n побит при сохранении. До фикса — избегайте этих символов в визуальном контенте.

Схемы алиаса: создание/удаление локальной схемы (переопределяет глобальную). Удаление — GET без CSRF (та же проблема, что у глобальных схем).

БД алиаса: статус подключения к MariaDB, количество таблиц, размер.

Глобальные разделы
Заглушки: менеджер HTML-файлов для 503. Создание, визуальное редактирование (HTML), удаление.

Безопасность: количество ошибок входа за 24ч, список активных банов (Rate Limit) с кнопкой «Разблокировать», настройки лимитов (max, window, ban).

Настройки: глобальные параметры (название сайта, язык).

Визуальный редактор (Low-Code)
Встроен для Страниц, Блоков и Схем. При сохранении JSON-структура компилируется в PHP (PageCompiler, RegionCompiler, SchemeCompiler).

Схемы: добавляйте слоты, выбирайте тег (div, header, main, ...) и CSS-класс. Сортировка ▲/▼.

🔴 Схлопывание вложенности (§6.15): при сохранении вложенная структура становится плоской. См. выше.

Блоки: контентные блоки (H1, H2, Текст, Картинка). Сортировка ▲/▼. Работает, данные не теряет.

Страницы: для каждого слота (из схемы) — статус:

Выключен — слот исчезает на странице.

Глобальный — используется базовый блок домена.

Локальный — раскрывается редактор, добавляйте свои блоки (H1, Текст и т.д.) только для этой страницы.

🔴 Перед первым визуальным сохранением любой страницы/блока/схемы — коммит в git. Это единственная защита от потери данных до закрытия P0 (MANIFEST.md §7.1).

Встроенный редактор кода
Все файлы (блоки, схемы, страницы, заглушки) открываются в CodeMirror:

Тёмная тема (Dracula).

Нумерация строк.

Подсветка PHP, HTML, CSS, JS. ⚠️ Для PHP используется MIME application/x-httpd-php — подсветка зависит от версии CodeMirror; если не работает, проверьте www/media/admin/codemirror/mode/meta.js.

Автозакрытие скобок.

Сохранение через «Сохранить» (POST + CSRF).

Аварийный режим (Safe Mode)
Если конфигурация (site.config, engine.config) повреждена или в коде критическая ошибка — админка не отдаёт белый экран. Вместо этого — красная страница с текстом ошибки и кнопкой «Попробовать снова».

⚠️ Safe Mode работает на уровне www/admin/index.php (try/catch вокруг всего bootstrap). Если ошибка возникла внутри контроллера админки — она будет поймана Kernel и вернёт 500, но не Safe Mode. Это ожидаемо.
