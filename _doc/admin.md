--- НАЧАЛО ДОКУМЕНТА ---

Руководство пользователя админки
Админка — это один из трех интерфейсов управления движком (остальные — CLI и AI-агент через `aicli.php`). 
Архитектурный принцип: Админка является «тонким клиентом». Она занимается только рендерингом HTML и валидацией форм. Все операции с файловой системой (создание, копирование, удаление, запись медиа) делегируются CLI-командам.

⚠️ Правило 3 файлов: Любая сущность в движке (Страница, Блок, Филлер, Схема) состоит из трех файлов: `{name}.php` (код), `{name}.rules.json` (настройки), `{name}.editor.json` (данные UI). Для страниц все три файла имеют единый префикс: `algoritm_{name}.{php,rules.json,editor.json}` в одной папке. Root — `algoritm/algoritm.{...}`. Глобальные манифесты (`blocks.json`, `schemes.json`) удалены.

⚠️ Медиа (`www/media/`): AI-картинки и другие медиа хранятся в `www/media/<domain>/<allias>/<category>/<hash>.<ext>` + `<hash>.meta.json`. Запись — только через CLI `media:store` (вызывается из AICLI, не из админки напрямую). Удаление — `media:remove --force` (в карантин `www/media/.trash/`). Скины и admin-ассеты (`www/media/<domain>/skin/`, `www/media/admin/`, `www/media/shared/`) — отдельные зоны, не смешиваются.

Панель управления
Доступна по адресу http://<ваш-домен>/admin/.

Вход в систему
При переходе открывается форма входа. Логин и пароль — из config/admin.config. По умолчанию: admin / secret (смените через php bin/cli.php admin:passwd).

⚠️ Валидация admin:passwd: логин 3-32 символа [a-zA-Z0-9_.-], пароль минимум 8 символов.

После 5 неудачных попыток IP блокируется на 15 минут (var/admin_fails.json). Все попытки (успешные и неуспешные) пишутся в var/admin_logs.json. Разблокировка — в разделе «Безопасность».

Админка использует отдельную авторизацию, независимую от пользователей сайта (user:new создаёт пользователей для страниц с "auth": true, а не для админки).

Шапка, Языки, Профиль
В верхней части — тёмная навигационная панель. Справа — переключатель языков (RU / EN / ZH). Выбор сохраняется в cookie admin_lang. Список языков — из admin.config.

Аватарка → меню:
- «Мой профиль»: Сводка, Логирование (история входов), Безопасность (смена пароля).
- «Выйти».

Обзор системы (System Health)
Раздел «Обзор» показывает статус доменов и алиасов деревом.
- Зелёный (OK) — всё работает.
- Жёлтый (Внимание) — warning (например, филлер включён, а слота в схеме нет; отсутствует .editor.json).
- Красный (Ошибка) — error (отсутствуют обязательные файлы, отсутствует root algoritm.rules.json).

Severity:
- `error` — критично: отсутствует `.php`, отсутствует `algoritm/algoritm.rules.json`, отсутствует схема.
- `warning` — некритично: отсутствует `.editor.json`, отсутствует `.rules.json` у блока/схемы, устаревший `{dir}/.rules.json` (→ `migrate:page-rules`), филлер без слота.

StructureChecker (источник данных «Обзора») проверяет:
- наличие всех 3 файлов (`algoritm_{name}.{php,rules.json,editor.json}`) для каждой страницы;
- наличие `algoritm/algoritm.rules.json` (root);
- отсутствие устаревших `{dir}/.rules.json`;
- стыковку филлер↔слот.

Уровень Домена
Главная «Домены» — список реальных доменов. Нажмите на название → панель управления.

Вкладки:
- Настройки: Заголовок, Статус сайта (вкл/выкл 503), Выбор заглушки, Время авто-включения, Удаление домена.
  ✅ Удаление домена вызывает CLI-команду `domain:remove` (с карантином и полной очисткой конфига — 16 ключей).
- Привязанные домены: управление входящими хостами. ⚠️ Порт и trailing-dot нормализуются (можно использовать IP:порт).
- Алиасы: список разделов. Переключатель статуса и переход в дашборд алиаса.
- Блоки (Глобальные): шаблонные элементы домена (top, left, center и т.д.). 
  ✅ Визуальный редактор удален в целях безопасности (защита от RCE). 
  Редактирование происходит только через CodeMirror (кнопка «Код»). Настройки типа (script/visual/mixed) хранятся в `{name}.rules.json`.
  ✅ Удаление блока вызывает `block:remove --force` (карантин в `.alliasglobal/<name>_trash_<ts>/`).
- Схемы (Глобальные): HTML-каркасы. Создание, копирование, удаление.
  ✅ Визуальный редактор схем (Drag&Drop) сохранен. Работает на основе `{name}.editor.json`, сохраняет вложенность (visual может содержать другие блоки, script — конечный лист).
  ✅ Кнопка «Создать схему» вызывает CLI-команду `scheme:new`.
  ✅ Кнопки «Копировать» и «Удалить» вызывают CLI-команды `scheme:copy` и `scheme:remove --force` (карантин в `.alliasscheme/<name>_trash_<ts>/`).
  ✅ Сохранение визуального редактора вызывает `scheme:save` (обновляет editor.json + компилирует php через SchemeCompiler).
- Медиа: просмотр `www/media/<domain>/<allias>/<category>/` (список). Только чтение — запись и удаление через CLI (`media:store` из AICLI, `media:remove --force` вручную). Показывает: hash, mime, размер, alt, source_url (из `<hash>.meta.json`). Ссылка «Скопировать local_url» (`/media/<domain>/<allias>/<category>/<hash>.<ext>`).
- БД домена: статус базы данных. (В разработке — заглушка.)
- Заглушки: HTML-файлы для 503. Создание, визуальное редактирование, удаление.

Уровень Алиаса
Нажмите на имя алиаса → дашборд.

Вкладки:
- Настройки: Заголовок, Статус алиаса, Заглушка, Активный скин, Разрешённые скины и языки.
- Блоки (Fillers): переопределения глобальных блоков. Кнопка «Синхронизировать» создаёт локальные файлы для всех глобальных блоков. Включить/Выключить: если выключено — используется глобальный блок. 
  ✅ Визуальный редактор удален. Редактирование только через CodeMirror.
  ✅ Включение/выключение вызывает `filler:toggle` (idempotent: не перезаписывает конфиг при том же значении).
- Страницы: Дерево страниц в algoritm/. Корень — `/` (`algoritm/algoritm.php`). Вложенные страницы отображаются с отступом.
  ✅ У каждой страницы в дереве есть кнопка «Код» (CodeMirror), а также переключатели Auth (🔒) и Search (🔍) в виде цветных пилюль. Переключение происходит через POST+CSRF и записывается в `algoritm_{name}.rules.json` (внутри — вызов CLI `page:toggle --name=... --parent=...`).
  ✅ Визуальный редактор страниц удален (в целях безопасности). Страницы пишутся только через код.
- Схемы алиаса: создание/удаление локальной схемы (переопределяет глобальную). Локальная схема хранится в `{name}.php` и `{name}.editor.json`.
- Медиа алиаса: список `www/media/<domain>/<allias>/`. Показывает категории и файлы. Только чтение.
- БД алиаса: статус подключения к MariaDB, количество таблиц, размер.

Глобальные разделы
- Заглушки: менеджер HTML-файлов для 503.
- Безопасность: количество ошибок входа за 24ч, список активных банов (Rate Limit) с кнопкой «Разблокировать».
- Медиа: глобальный обзор `www/media/` по всем доменам. Показывает: домен, алиас, категория, количество файлов, размер. Только чтение.
- Настройки: глобальные параметры (название сайта, язык).

Встроенный редактор кода (CodeMirror)
Единственный инструмент для правки Страниц, Блоков и Филлеров. Открывается по кнопке «Код» или «Редактировать».
- Тёмная тема (Dracula).
- Нумерация строк.
- Подсветка PHP, HTML, CSS, JS.
- Автозакрытие скобок.
- Сохранение через «Сохранить» (POST + CSRF).

Визуальный редактор (Low-Code) — Только для Схем
Drag&Drop доступен только в разделе «Схемы». 
- Зоны: «Неактивные», «Скрипты» и «Визуал».
- Вы можете перетаскивать блоки в canvas, настраивать CSS-классы и вложенность.
- При сохранении JSON-структура из `{name}.editor.json` обновляется, и CLI-команда `scheme:save` компилирует её в чистый PHP (через SchemeCompiler).

Медиа (www/media/) — просмотр
- В админке — **только просмотр** (список категорий, файлов, метаданные).
- Запись — через AI (`image:download` → `media:store`) или вручную через CLI (`media:store --data_b64=...`).
- Удаление — через CLI (`media:remove --force`, карантин в `www/media/.trash/`).
- Три зоны не смешиваются: `admin/`, `shared/`, `<domain>/skin/` (git, руками) vs `<domain>/<allias>/<category>/` (runtime, .gitignore) vs `.trash/` (карантин).
- Очистка карантина медиа — через `trash:clear --force` (5-й уровень).

Аварийный режим (Safe Mode)
Если конфигурация повреждена или в коде критическая ошибка — админка не отдаёт белый экран. Вместо этого — красная страница с текстом ошибки и кнопкой «Попробовать снова».
⚠️ Safe Mode работает на уровне www/admin/index.php (try/catch вокруг bootstrap).

Что НЕ работает в админке (ограничения)
- Создание пользователей сайта (user:new) — только CLI.
- Миграции БД (db:migrate) — только CLI.
- Очистка карантина (trash:clear) — только CLI.
- Миграция .rules.json (migrate:page-rules) — только CLI.
- Запись медиа (media:store) — только CLI (из AICLI) или вручную.
- Удаление медиа (media:remove) — только CLI.
- Копирование/удаление схем — через CLI (scheme:copy/remove), но кнопки в админке вызывают CLI.

Что делать при ошибках
Если вы видите ошибку структуры (жёлтый/красный статус) — запустите в терминале:
`php bin/cli.php structure:check` (диагностика; warning ≠ error, exit 0 при отсутствии errors).

Автовосстановление отсутствующих `.rules.json`/`.editor.json` (и root-страниц через PageCompiler):
`php bin/cli.php structure:repair --domain=example.ru`.

Если в выводе structure:check есть warning «Устаревший /X/.rules.json — запустите migrate:page-rules» — выполните:
`php bin/cli.php migrate:page-rules` (переводит старые `.rules.json` на новую модель). Команда идемпотентна. Для предпросмотра — `--dry`.

Очистка карантина (папки `*_trash_<timestamp>/`):
`php bin/cli.php trash:clear` (dry-run по умолчанию).
`php bin/cli.php trash:clear --force --older=7d` (боевой, только старше 7 дней).
`php bin/cli.php trash:clear --force --domain=example.ru` (только один домен).

Карантин существует на 5 уровнях:
- `app/<domain>_trash_<ts>/` (domain:remove)
- `app/<domain>/<allias>_trash_<ts>/` (allias:remove)
- `app/<domain>/.alliasscheme/<name>_trash_<ts>/` (scheme:remove)
- `app/<domain>/.alliasglobal/<name>_trash_<ts>/` (block:remove)
- `www/media/.trash/<domain>_<allias>_<category>_<hash>_trash_<ts>/` (media:remove)

Медиа (просмотр / удаление):
`php bin/cli.php media:list --domain=example.ru [--allias=www] [--category=coffee]`
`php bin/cli.php media:remove --domain=example.ru --allias=www --category=coffee --hash=a3f5c1e9 --force`
