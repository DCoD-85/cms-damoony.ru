# Архитектура Progressive Enhancement (JS on / JS off)

Данный документ описывает только JS-слой (файл `app.js`) и работу с `MinStruct`. 
Базовый контракт `Page::content()` и `$ajaxBlocks` описан в `_doc/dev.md` §2.

## 1. Принцип работы `app.js`
Скрипт перехватывает клики по ссылкам и отправку форм, добавляя заголовок `X-Requested-With: XMLHttpRequest`.
- Если JS включен, сервер возвращает JSON. `app.js` заменяет HTML в нужных блоках и обновляет URL через `history.pushState`.
- Если JS выключен, форма или ссылка работает стандартным GET/POST запросом с полной перезагрузкой страницы (SSR).

## 2. Обработка ответов (MinStruct)
При AJAX-отправке формы сервер возвращает `MinStruct`:
- `messages` — HTML для всплывающей плашки (Toast).
- `release` — HTML для замены контента (например, "Спасибо").
- `form.redirect` — URL для перехода после успеха.
- `reload` — принудительная перезагрузка страницы (если нужно сбросить сложный стейт).

## 3. Всплывающие плашки (Toasts)
Стили лежат в `toast.css` (подключается через схему). 
При серверной загрузке плашки берутся из `flash-data`, при AJAX-запросах — из поля `messages`.


## 4. AJAX-навигация (cliajax.js)

Скрипт `www/media/shared/scripts/cliajax.js` отвечает за прогрессивное улучшение (SPA-эффект без фреймворков).

**Как работает:**
1. Перехватывает клики по `<a>` и отправку `<form>`.
2. Отправляет `fetch` с заголовком `X-Requested-With: XMLHttpRequest`.
3. Если сервер вернул JSON (MinStruct), скрипт заменяет HTML в блоках по атрибуту `[data-block="name"]`.
4. Обновляет URL через `history.pushState` (для ссылок).

**Бенчмарк:**
В правом нижнем углу выводится плашка `⚡ [время последнего] / [общее время] / [кол-во AJAX]`. 

**CSRF-защита:**
Все POST-формы должны содержать скрытое поле `_csrf`. `PageHandler` блокирует запросы без токена (403).
