# AIUI (AI User Interface)

AIUI — интерфейс для редактирования страниц с помощью естественного языка (промптов). 
Пользователь не пишет PHP-код и не редактирует JSON вручную, а общается с LLM, которая перестраивает блоки страницы.

См. также: `_doc/orchestrator.md` (внутренний конвейер), `_doc/ai.md` §8 (связь с AI-слоем).

---

## 1. Архитектура

1. **Frontend (`www/admin/aiui.php`)**: Split-screen интерфейс. Слева — iframe с предпросмотром, справа — чат. Собирается через `Builder`.
2. **JS (`www/media/damoony.ru/agent/skin/default/js/aiui.js`)**: Логика чата, кнопки «Создать», отправки промптов.
3. **AJAX Endpoint (`www/admin/ai_edit.php`)**: Принимает POST с JSON `{action, domain, alias, page, tab, prompt}`.
4. **Backend (Orchestrator)**: `Orchestrator::run()` (для чата) или `Orchestrator::build()` (для генерации по кнопке).
5. **Preview (`www/admin/aipreview.php`)**: Рендерит HTML из изолированной сессии (`.sess_*`).

---

## 2. UI Элементы

1. **Чат (правая панель)**: История диалога. ИИ задает вопросы, пользователь отвечает.
2. **Панель брифа (📝)**: Появляется над полем ввода, как только ИИ накопил первые требования. Показывает краткое содержание того, что ИИ понял.
3. **Кнопка «🚀 Создать сайт по брифу»**: Появляется, когда бриф не пустой. Запускает тяжелый конвейер генерации (Architect -> Coder).
4. **Кнопка «Применить»**: Появляется в шапке превью после успешной генерации. Переносит изменения из сессии в production.

---

## 3. API Endpoint — 4 action

`POST /admin/ai_edit.php`

- **`start`**: Создать сессию (копия домена в `.sess_*`). Возвращает `{ok, tab, preview_url}`. Если сессия уже есть, она уходит в карантин и создается новая.
- **`preview`**: Интерактивный шаг (`Orchestrator::run()`).
  - Если ИИ просто общается: `{ok, chat_only: true, reply, brief}`. Превью НЕ обновляется.
  - Если ИИ сгенерировал страницу (по команде в чате): `{ok, preview_url, pages_total, pages_ok, progress}`.
- **`build`**: Явная генерация по кнопке (`Orchestrator::build()`). Возвращает прогресс по страницам.
- **`apply`**: Применить сессию к production (`SessionApplyCommand`). Заблокировано, если блоков меньше 5 (защита от пустых страниц).

---

## 4. Изоляция (Sessions)

- При `action=start` создается копия домена: `app/.sess_{tab}.{domain}/` и `www/media/.sess_{tab}.{domain}/`.
- Все команды записи (`page:new`, `page:write`) выполняются с флагом `--session={tab}`. Они физически не могут изменить production.
- Превью рендерится из `app/.sess_{tab}.{domain}/www/algoritm/`.
- При нажатии «Применить» папка сессии перемещается в production (старая уходит в `_trash_`).

---

## 5. E2E Сценарий (как это работает для пользователя)

1. Пользователь пишет: «Привет, нужен сайт кофейни».
2. ИИ (Интервьюер) отвечает: «Отлично! Какой стиль?» -> Панель брифа показывает: `Сайт кофейни`.
3. Пользователь: «Винтаж, меню и контакты».
4. ИИ обновляет бриф -> Панель брифа: `Сайт кофейни, винтаж, меню, контакты`.
5. Появляется кнопка «Создать сайт». Пользователь жмет.
6. Запускается Архитектор (создает план страниц) и Кодер (пишет блоки для каждой страницы).
7. В чате появляются галочки: `✓ home`, `✓ menu`, `✓ contacts`.
8. Превью обновляется. Пользователь смотрит и жмет «Применить». Изменения в проде.

## 6. Безопасность и Ограничения

### 6.1. Безопасность (что гарантировано)

- **Никакого raw PHP.** ИИ отдаёт только JSON, `BlockCodegen` генерирует PHP безопасно через `Builder`.
- **Валидация JSON.** Если LLM вернул мусор, сессия падает с ошибкой, production не перезаписывается.
- **Сессии изолированы.** `page:new`/`page:write` идут с `--session=X`, пишут в `.sess_*`. Без `apply` production не тронут.
- **Защита от пустого `apply`.** `action=apply` блокируется, если рекурсивный `countBlocks()` < 5 (чтобы не затереть прод пустой страницей).
- **Лимиты времени.** Для локальных LLM (DeepSeek/Gemma) таймауты подняты до 600с (10 минут) в `php.ini`, `nginx.conf` и `AgentChatHandler`.

### 6.2. Ограничения (что НЕ работает)

- **Стили не генерируются.** `DesignerAgent` в Orchestrator отсутствует. AIUI использует skin по умолчанию (голый HTML без CSS). Для стилей — `skin:new` + `skin:edit` вручную, или Wizard (`brain.py`), где стили генерируются.
- **Нет Undo / rollback.** После неудачной генерации — только `git` или `session:discard` (карантин). Кнопки «Отменить сборку» в UI пока нет.
- **`build_partial` возможен.** Если 3/5 страниц упали (ошибка LLM/валидации), они остаются в сессии со статусом `failed` в `meta.build_progress`. Пользователь должен проверить `context.json` и пересобрать вручную или очистить сессию.
- **Markdown не всегда снимается.** `stripMarkdown()` в `CoderAgent` покрывает `**bold**`, `*italic*`, `` `code` ``, `[text](url)`, `# headers`. Списки, цитаты, таблицы — могут остаться.
- **Архитектор нестабилен по именам.** Разные запуски → разные имена страниц (`about` vs `company_info` vs `our_coffee`). Не влияет на рендеринг, но затрудняет навигацию.
- **Coder оборачивает в `section`.** LLM иногда возвращает `[{"type":"section","children":[...]}]` вместо плоского массива. Валидно, но `build_progress.blocks` показывает 1 (верхний уровень).
- **`PageNewCommand --session` на Windows требует рестарт PHP-CGI.** После изменения PHP-класса opcache не перечитывает, пока не перезапустишь трей.

### 6.3. Рекомендации пользователю

- Проверять бриф перед «🚀 Создать сайт» — иначе AI уйдёт не туда.
- После генерации — смотреть `context.json` (`meta.build_progress`), убедиться, что все страницы `done`.
- Стили — отдельным шагом (`skin:new` + `skin:edit`), либо использовать Wizard (`brain.py`), где CSS генерируется.
- Если AI «сломал» сессию — `session:discard` и начать заново, либо `session:apply` только после проверки превью.
