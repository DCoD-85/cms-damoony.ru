# Философия проекта Damoony

Источник: `_devdoc/_auditfinal/` (36 файлов, покрытие 83 файлов `_audit`).
Документ фиксирует принципы старого проекта, которые переносятся в новый движок. Код и реализации не переносятся — переносятся принципы и контракты.

---

## 1. Домен — единица организации

Всё в проекте вращается вокруг домена и алиаса. Домен — верхний уровень, алиас — рабочая единица (сайт, версия, язык, скин). Роутинг, схемы, регионы, filler, датапровайдеры, БД — всё скоупится по домену/алиасу.

Следствие: движок обязан иметь `DomainResolver` как точку входа и не хардкодить имена доменов.

Источник: `_auditfinal/05`, `_auditfinal/30`, `_auditfinal/32`, `_auditfinal/35`.

---

## 2. UI — это дерево, а не текст

Представление строится как типизированное дерево узлов (visuotag/visuoel), а не как строковый шаблон. Узлы имеют атрибуты, мета, структуру, действия. Рендер — финальный шаг, не источник истины.

Следствие: никаких Twig/Blade. UI-слой — PHP-DOM с явными типами.

Источник: `_auditfinal/25`, `_auditfinal/26`, `_auditfinal/27`, `_auditfinal/28`, `_auditfinal/29`.

---

## 3. Регионы и filler — плагины шаблона

Шаблон домена состоит из именованных регионов (top, left, center, right, bottom, policy, debug). Каждый регион — блок с контрактом. Filler — переопределение региона для конкретного алиаса. Схема — каркас страницы, собираемый из регионов.

Следствие: регион — единица расширения. Ядро не знает о конкретных регионах, знает о контракте `Region`.

Источник: `_auditfinal/34`, `_auditfinal/35`.

---

## 4. Роутинг — файловые правила

Страницы живут в файловой иерархии `algoritm/`. Правила — в `.rules.json` рядом. Роутер читает правила, идёт по сегментам URL, вызывает `default()`. Regex-параметры, auth-флаг, namespace домена — часть контракта.

Следствие: никакого `routes.php` с сотнями строк. Конфигурация роутинга — данные, не код.

Источник: `_auditfinal/08`.

---

## 5. Один способ сделать что-то

Проект страдал от двух БД-слоёв, двух путей фронта, двух автозагрузчиков, двух роутеров. Новый движок фиксирует: одна точка входа на задачу.

Следствие: если появляется второй способ — первый удаляется или помечается `#[Deprecated]` с датой удаления.

Источник: `_auditfinal/03`, `_auditfinal/09`, `_auditfinal/25`, `_auditfinal/36`.

---

## 6. Explicit over implicit

Никаких `$GLOBALS`, статических кэшей, магических методов `__get` на критичных объектах, скрытых зависимостей. Всё, что нужно — передаётся явно через конструктор. Контейнер — удобство сборки, не источник состояния.

Следствие: класс без конструктора с зависимостями считается ошибкой проектирования.

Источник: `_auditfinal/05`, `_auditfinal/18`, `_auditfinal/23`, `_auditfinal/33`.

---

## 7. Контракт-first

Публичный API — интерфейсы, не классы. Реализация — деталь. Каждый модуль имеет один публичный вход (facade или interface) и не более. Внутренности модуля — private.

Следствие: публичный класс без интерфейса — ошибка. Расширение публичного API — только через новый интерфейс.

Источник: `_auditfinal/04`, `_auditfinal/23`, `_auditfinal/24`.

---

## 8. CLI — первый класс

Управление проектом (создание домена, алиаса, блока, страницы, миграции, настройки) — через CLI, не через веб-админку. Веб-админка — надстройка над теми же командами. Каждая команда: `plan` + `run`, `Context` для шагов, `Result` для отчёта, `--dry-run` и `--json` по умолчанию.

Следствие: любая операция, доступная в админке, доступна в CLI. Обратное не обязано быть верным.

Источник: `_auditfinal/09`, `_auditfinal/10`, `_auditfinal/11`, `_auditfinal/12`, `_auditfinal/13`, `_auditfinal/14`.

---

## 9. Безопасность — не фича, а основа

Секреты — только в `secure/`, вне public. Пароли — `password_hash`/`password_verify`, не сырое сравнение. CSRF — на всех POST. Удаление — только POST, не GET. Загрузки — whitelist расширений и проверка mime. Fingerprint-устройства, приглашения, аудит — часть ядра.

Следствие: новый движок не наследует уязвимости старого (`phpinfo`, пароль из cookie, GET-delete, svg без заголовков).

Источник: `_auditfinal/07`, `_auditfinal/18`, `_auditfinal/21`.

---

## 10. Идемпотентность и откат

Операции, меняющие состояние (`*:new`, `*:sync`, `*:extract`), должны быть идемпотентны или безопасно повторяемы. Разрушительные операции — через карантин (rename в trash) с откатом при ошибке. Мутации конфигов — под lock, атомарно.

Следствие: `*:remove` без карантина и lock считается багом.

Источник: `_auditfinal/11`, `_auditfinal/12`, `_auditfinal/14`, `_auditfinal/23`.

---

## Что НЕ переносится

- `$GLOBALS`, `DS`/`DSA` как глобальные шорткаты, глобальные `error()`/`error_file()`.
- Classmap autoload и глобальные имена классов (`main`, `tree`, `db`).
- Два БД-слоя, два пути фронта, два роутера.
- Regex-патчинг PHP-файлов для генерации кода.
- Twig/Blade-подобные шаблоны (их и не было, но фиксируем явно).
- Laravel/Symfony/Doctrine/Eloquent как зависимости.

## Что переносится как идея, но реализуется заново

- visuo — как PHP-DOM с типами, но новый код.
- alliasglobal + filler — как контракт `Region` + `Filler`.
- alliasscheme — как контракт `Scheme` через декларативные манифесты.
- tree — как файловый роутер с `.rules.json`.
- corescripts CLI — как контракт `plan/run`, но новый код.
- dataprovider — как контракт `Repository` на PDO.

## Стек нового движка

PHP 8.4, Composer (PSR-4), PSR-3, PSR-11, PSR-7/15 (по необходимости), PHPUnit 10+, PHPStan 8, PHP-CS-Fixer (PSR-12), PDO (SQLite dev / MySQL prod), nginx + php-fpm, Docker для dev/staging.
