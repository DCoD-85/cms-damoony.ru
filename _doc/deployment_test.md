# Полный сценарий развертывания (E2E)

Документ описывает полный цикл тестирования и развертывания движка: **Локальный вендор -> Боевой вендор -> Боевой клиент**.

Для понимания архитектуры смотрите arch.md, для установки в dev-окружении — install.md. Данный документ является чек-листом для релиза.

## 1. Роли и окружения

- **Локальный вендор** (damoonyserver.ru / damoony.ru локально) — среда разработки, где тестируются скрипты.
- **Боевой вендор** (damoony.ru) — сервер, раздающий лицензии и архивы.
- **Боевой клиент** (idoam.ru) — чистый сервер, куда устанавливается движок.

## 2. Подготовка Локального Вендора

1. Убедитесь, что все тесты проходят: composer test.
2. Проверьте целостность структуры:
   php bin/cli.php system:scan
   *В корне проекта не должно быть мусора (old_backup, trash_v3 и т.д.).*
3. Соберите ZIP-архив локально:
   php _dist/packager.php
4. Проверьте содержимое архива (внутри должен быть vendor/autoload.php и bin/cli.php, но не должно быть _dev и ai_agent):
   unzip -l www/downloads/core-v4.zip | head -n 20

## 3. Деплой на Боевой Вендор (damoony.ru)

Зайдите на боевой сервер по SSH.

1. Обновите код из Git:
   cd /var/www/damoony.ru
   git pull origin main
2. Установите зависимости (если папки vendor нет):
   php composer.phar install --no-dev --optimize-autoloader
3. Разверните файлы вендора в webroot:
   bash _dist/vendor/deploy.sh
4. Убедитесь, что у веб-сервера есть права на запись лицензий:
   chown -R www-data:www-data /var/www/damoony.ru/data/
   chmod -R 775 /var/www/damoony.ru/data/
5. Соберите боевой ZIP-архив:
   php _dist/packager.php

## 4. Установка на Боевой Клиент (idoam.ru)

1. Откройте в браузере https://damoony.ru/request.php. Заполните форму (домен клиента) и скачайте скрипт установки (install-domen.ru.sh).
2. Закиньте скрипт на сервер клиента (в пустую папку проекта, например /var/www/idoam.ru/).
3. Запустите установку:
   cd /var/www/idoam.ru/
   bash install-domen.ru.sh
   *(Скрипт сам создаст БД, скачает чистый ZIP, развернет структуру и сгенерирует CREDENTIALS.txt).*
4. Проверьте состояние клиента:
   php bin/cli.php system:scan
   *Ожидаемый результат: ПРОЕКТ В ИДЕАЛЬНОМ СОСТОЯНИИ.*

## 5. Известные ограничения при развертывании (Troubleshooting)

- **Ошибка SSL:** Если сервер клиента не имеет CA-сертификатов, install.sh автоматически переключится на curl -k (с предупреждением в консоли). Это нормально для закрытых тестовых сред.
- **Отсутствует vendor/autoload.php:** Архив собирается из того, что лежит на диске. Если на вендоре не запускался composer install, архив будет пустым.
- **Invalid license:** Возникает, если PHP (пользователь www-data) не может записать ключ в data/licenses.json. Проверьте права на папку data/.
