## 1. Цель и границы

**Входит:**
- `src/Db/DataProvider/` — Repository pattern (ядро, owner-only).
- `app/[domain]/[alias]/provider/` — кастомные провайдеры (AI генерирует, dev пишет).
- Introspection: `db:schema`, `db:methods`, `db:describe` (read-only).
- Safe invocation: `db:call`, `db:mutate` (через DataProvider).
- Method generation: `dataprovider:add-method` (templates only).
- Phase 0 (предусловие): refactor `bin/aicli.php` (812 → handlers).
- Wizard multi-session: admin-only, per-session rate limit, файлы + TTL.

**Не входит (v3.2+):**
- AINET расширение (POST, HTML parsing).
- Multi-agent hierarchy (`roadmap.md` п.4).
- Визуализация Builder (form/table/select).
- `CREATE/DROP/ALTER TABLE` через AI (`db:migrate` — отдельно).
- Public wizard UI.
- Полноценный поиск (Meilisearch — v3.2).

## 2. DB Architecture

### 2.1. Единая БД + префиксы

```
damoony_main
├── users, sessions, roles, user_roles, login_attempts   ← глобальные (SSO)
├── domains, aliases                                       ← реестр
├── d1_www__news, d1_www__doc_articles, ...               ← alias-данные
├── d1_doc__articles, d1_doc__sections, ...
├── d2_www__news, d2_shop__orders, ...
└── d3_www__news, ...
```

**Правило:** `d{N}_{alias}__{table}` — alias-данные. Глобальные
таблицы (`users`, `sessions`) — без префикса.

### 2.2. Инварианты (инфорцируются в `arch.md`)

1. Всё взаимодействие с БД — **только** через `DataProvider`. Никакого
   raw SQL в страницах, контроллерах, регионах.
2. Cross-alias FK — **запрещены**.
3. `JOIN` разрешён:
   - внутри одного alias (`d1_www__doc_articles JOIN d1_www__doc_views`);
   - с глобальной таблицей (`d1_www__audit_log LEFT JOIN users`).
4. Транзакции — **внутри одного alias**.
5. `site.config.domains_aliases_storage` — mapping `{db, prefix}`.
   Переезд alias в отдельную БД = изменение конфига, не кода.

### 2.3. Конфиг (фрагмент `site.config`)

```
"domains_aliases_storage": {
  "damoony.ru": {
    "www": { "db": "main", "prefix": "d1_www__" },
    "doc": { "db": "main", "prefix": "d1_doc__" }
  }
}
```

`db: "main"` = `engine.config.db.dbname`. Завтра `db: "damoony_doc"` —
отдельная БД. Код не меняется.

### 2.4. Refactorability

Переезд alias `doc` в отдельную БД:
1. `mysqldump d1_doc__*` → `damoony_doc`.
2. `site.config`: `"doc": { "db": "damoony_doc", "prefix": "" }`.
3. Провайдер видит конфиг, `physicalTable()` возвращает `articles`.
4. Код не меняется.

**Что ломает refactorability:** raw SQL вне провайдера, cross-alias FK,
транзакции между alias, хардкод имени БД в SQL.

## 3. DataProvider

### 3.1. Структура (core + custom)

```
src/Db/DataProvider/                    ← ЯДРО (owner-only, git)
├── AbstractProvider.php                 — query(), physicalTable()
├── ProviderInterface.php                 — table(), physicalTable()
├── ProviderRegistry.php                 — резолвит (domain, alias, provider): core → custom
├── UserProvider.php                     — Phase 1.1
├── NewsProvider.php                     — Phase 1.2
├── DocProvider.php                      — Phase 1.3 (fail fast)
├── FilesProvider.php                    — Phase 1.4
├── StatsProvider.php                    — Phase 1.5 (JOIN alias-уровня)
├── AuditProvider.php                    — Phase 1.6 (LEFT JOIN global)
└── Template/
    ├── TemplateInterface.php
    └── (12 шаблонов, см. §4)

app/[domain]/[alias]/provider/          ← ПЕРИФЕРИЯ (AI генерирует, dev пишет, git)
├── NewsProvider.php                     — extends Damoony\Db\DataProvider\NewsProvider
└── CustomLogicProvider.php              — уникальная бизнес-логика
```

**Резолвинг:** `ProviderRegistry` сначала смотрит в `app/.../provider/`,
если нет — в `src/Db/DataProvider/`. Кастомный провайдер **расширяет**
базовый (наследование), не заменяет.

### 3.2. Контракт

`ProviderInterface`:
- `table(): string` — логическое имя (`news`).
- `physicalTable(): string` — физическое (`d1_www__news`), из конфига.

`AbstractProvider`:
- `__construct(Paths $paths, Config $site, string $domain, string $alias)`.
- `protected query(string $sql, array $params): PDOStatement`.
- `protected physicalTable(): string` — резолвинг через
  `site.config.domains_aliases_storage`.

### 3.3. Провайдеры (методы)

**UserProvider:** `by_login`, `by_id`, `exists`, `create`, `assign_role`,
`has_role`, `session_create`, `session_find`, `session_drop`,
`check_bruteforce`, `record_login_attempt`.

**NewsProvider:** `recent`, `by_slug`, `by_id`, `create`, `update`,
`publish`, `archive`, `delete`, `search_like`.

**DocProvider:** `section_by_slug`, `sections_tree`, `articles_by_section`,
`articles_recent`, `article_create`, `article_update`, `article_publish`,
`versions`, `version_create`, `version_by_id`.

**FilesProvider:** `all_active`, `by_slug`, `create`, `update_filesize`,
`increment_downloads` (log + counter), `downloads_stats`, `delete`.

**StatsProvider:** `view_log`, `views_count`, `views_total`, `views_recent`,
`top_articles` (JOIN `doc_articles + doc_views`, alias-уровень).

**AuditProvider:** `log`, `recent` (LEFT JOIN global `users`),
`by_entity`, `by_user`.

### 3.4. Порядок реализации — fail fast

1. **User** — базовый CRUD, обкатка шаблонов.
2. **News** — status transitions, lang.
3. **Doc** — **fail fast:** иерархия + versions. Если шаблоны не покрывают —
   правим сейчас, не после 4 провайдеров.
4. **Files** — log + counter (`insert` + `update` increment).
5. **Stats** — `join_select` alias-уровня.
6. **Audit** — `join_select` global.

### 3.5. Кто что пишет

| Что | Кто | Где |
|---|---|---|
| Базовые CRUD (шаблоны) | AI (`dataprovider:add-method`) **или** dev (CLI) | `app/.../provider/` |
| Сложная логика (`check_bruteforce`, `filter_writable`) | **только dev**, руками PHP | `app/.../provider/` |
| 6 базовых провайдеров | **только owner**, руками PHP | `src/Db/DataProvider/` |

**AI никогда не пишет PHP.** AI: вызывает готовые методы (`db:call`,
`db:mutate`), генерирует новые **из шаблонов** (`dataprovider:add-method`).

**Dev:** пишет кастомную логику в `app/.../provider/`, использует CLI
для генерации рутины, **не трогает** `src/Db/DataProvider/` без ревью.

**Почему не только CLI:** `check_bruteforce` = SQL с `DATE_SUB`,
`OR login`, интервалами. Шаблон `count` покроет 80%, но не 100%.
Шаблоны для рутины, PHP для сложного.

## 4. Templates (12 шаблонов)

Каждый — класс `src/Db/DataProvider/Template/`, реализует
`TemplateInterface::compile(array $params): array{sql: string, bindings: array}`.

**Никакой конкатенации пользовательских значений** — только PDO named params.

| # | Шаблон | Пример SQL |
|---|---|---|
| 1 | `select_by` | `WHERE :col = :val LIMIT 1` |
| 2 | `select_where` | `WHERE <conditions> ORDER BY <order> LIMIT :limit` |
| 3 | `select_all` | `SELECT <fields> FROM <table> ORDER BY <order> LIMIT :limit` |
| 4 | `insert` | `INSERT INTO <table> (<cols>) VALUES (:param...)` |
| 5 | `update` | `UPDATE <table> SET <sets> WHERE <conditions>` |
| 6 | `delete` | `DELETE FROM <table> WHERE <conditions>` |
| 7 | `count` | `SELECT COUNT(*) FROM <table> WHERE <conditions>` |
| 8 | `exists` | `SELECT 1 FROM <table> WHERE <conditions> LIMIT 1` |
| 9 | `aggregate` | `SELECT <fn>(<col>) FROM <table> WHERE <conditions>` |
| 10 | `join_select` | `SELECT ... FROM <a> <type> JOIN <b> ON <on> WHERE ...` |
| 11 | `group_by_count` | `SELECT <col>, COUNT(*) ... GROUP BY <col>` |
| 12 | `sum_by` | `SELECT <col>, SUM(<field>) ... GROUP BY <col>` |

**Статус (04.11.2026):** реализован только **`select_where`**. Остальные 11
шаблонов — Phase 4.2. E2E подтверждён: AI генерирует `published_ru` в
`app/damoony.ru/www/provider/NewsProvider.php` через `dataprovider:add-method`,
`ProviderResolver` подхватывает, `db:call` возвращает данные.

### 4.1. Операторы (для `where[]`)

`=`, `!=`, `<`, `>`, `<=`, `>=`, `LIKE`, `IN`, `IS NULL`, `IS NOT NULL`.

Значения — только через bindings. Операторы — из whitelist.

### 4.2. Join-type (шаблон 10)

- `join_type: "alias"` — обе таблицы в одном alias (разрешено).
- `join_type: "global"` — вторая — глобальная (разрешено).
- Cross-alias — **ошибка компиляции**.

### 4.3. Почему не FULLTEXT

`MATCH ... AGAINST` — устаревает. Для v3.1 — `LIKE` через `select_where`
(`op: "LIKE"`). Полноценный поиск (Meilisearch через AINET) — v3.2.

## 5. Phase 0 — Refactor AICLI

### 5.1. Цель

`bin/aicli.php` 812 строк, 40+ if-блоков, двойной subprocess
(`proc_open` + `shell_exec`) → разбить на handlers.

### 5.2. Структура

```
bin/aicli.php                    — bootstrap + role check + dispatch (~60 строк)
src/Ai/Aicli/
├── AicliHandlerInterface.php     — command(): string, handle(args, role): AicliResult
├── AicliResult.php                — readonly DTO: ok, data, error, hint
├── HandlerRegistry.php            — dispatch по command
├── AicliClient.php                — заменяет runCli/runCliJson
└── Handler/
    ├── WizardStartHandler.php
    ├── WizardStepHandler.php
    ├── DomainHandler.php
    ├── PageHandler.php
    ├── BlockHandler.php
    ├── FillerHandler.php
    ├── SchemeHandler.php
    ├── SkinHandler.php
    ├── ContentHandler.php
    ├── NetHandler.php
    ├── AgentChatHandler.php
    ├── AiStartHandler.php
    ├── DoneHandler.php
    ├── EngineStatusHandler.php
    └── StructureHandler.php
```

### 5.3. Правила

- Каждый handler — один файл, один `command()` (или группа родственных).
- `AicliClient` — инъекция в handlers (тестируется без `proc_open`).
- `Roles::whitelist()` — источник истины (не меняется).
- `AicliCoverageTest` продолжает работать.

### 5.4. Атомарность

Все handlers + refactor `bin/aicli.php` — **один коммит**. Откат = один
`git revert`. Постепенный refactor = 2× работа + риск промежуточных состояний.

## 6. API AICLI-команд (v3.1)

**`db:*` — команды `bin/cli.php`** (не `dbcli.php`, не `aicli.php`).
`bin/aicli.php` — только policy (role whitelist + JSON), `bin/cli.php` —
механизм (SQL). Разделение: AI-слой знает о ролях, CLI — нет.

### 6.1. Команды `bin/cli.php`

| Команда | Назначение | Dry-run |
|---|---|---|
| `db:schema --domain --alias` | Список таблиц + колонок (из `information_schema`) | — |
| `db:methods --domain --alias --provider` | Список методов провайдера | — |
| `db:describe --domain --alias --provider --method` | Params + return type | — |
| `db:call --domain --alias --provider --method --params='{}'` | Read-only | ✅ |
| `db:mutate --domain --alias --provider --method --params='{}' --force` | Write | ✅ |
| `dataprovider:add-method --domain --alias --provider --template=... --args='{}'` | Генерация метода | ✅ |

**`bin/cli.php` растёт на 6 строк** (`$registry->add(...)`). Логика —
в `src/Cli/Commands/Db*/`, провайдеры — в `src/Db/DataProvider/`.

### 6.2. Роли (в `bin/aicli.php`)

| Команда | Роль |
|---|---|
| `db:schema`, `db:methods`, `db:describe` | inspector |
| `db:call` | inspector, executor, reporter |
| `db:mutate` | executor (`--force`) |
| `dataprovider:add-method` | architect |

### 6.3. Формат запроса (через aicli)

```
{
  "command": "db:call",
  "role": "inspector",
  "args": {
    "domain": "damoony.ru",
    "alias": "www",
    "provider": "news",
    "method": "recent",
    "params": { "limit": 10 }
  }
}
```

### 6.4. Формат ответа

```
{
  "ok": true,
  "data": { "rows": [...], "count": 5 },
  "error": "", "hint": "",
  "role": "inspector",
  "next": [...]
}
```

### 6.5. Безопасность

- `db:call` — только read-шаблоны (1–3, 7–12). Write — через `db:mutate`.
- `db:mutate` — только `--force` + роль `executor`. Write-операции
  логируются в `audit_log`.
- `dataprovider:add-method` — только templates. AI не пишет PHP.

## 7. Wizard multi-session

Wizard UI живёт в `app/[domain]/[alias]/algoritm/ajax/algoritm_ajax.php`
(per-alias). Сессия привязана к `(domain, alias)`.

| Аспект | Решение |
|---|---|
| Доступ | Admin-only (`ADMINSESSID` + `admin_login`) |
| Storage | `var/wizard/{domain}/{alias}/{session_id}.json` + TTL 24h |
| Rate limit | Per `admin_session_id` (не per-IP) |
| Cleanup | `wizard:gc` → карантин `var/wizard/{domain}/{alias}/_trash_[ts]/` |
| Изоляция | `WizardSession.meta.admin_session_id` + проверка при каждом шаге |
| Лимит сессий | 3 активных на admin на alias (настраивается) |

### 7.1. Привязка

`WizardSession::create()` пишет в meta:

```
{
  "session_id": "...",
  "domain": "...",
  "alias": "...",
  "admin_login": "...",
  "admin_session_id": "...",
  "created_at": "...",
  "stage": "init"
}
```

При `wizard:step` — проверка: `meta.admin_session_id === current ADMINSESSID`
**и** `meta.domain/alias` совпадают с args. Иначе `403`.

### 7.2. Rate limit

Отдельный `WizardRateLimitMiddleware` (не общий `RateLimitMiddleware`).
Считает по `ADMINSESSID`, не по IP. Default: 60/min.

## 9. Риски и mitigation

| Риск | Mitigation |
|---|---|
| RCE через генерацию | Templates only, AI не пишет PHP |
| SQL injection | PDO named params, никакой конкатенации |
| Битые миграции | Никаких CREATE/DROP/ALTER через AI |
| AICLI монолит растёт | Phase 0 — предусловие |
| Cross-alias FK ломает переезд | Запрещены, инфорцируется в `arch.md` |
| Wizard abuse | Admin-only + per-session rate limit |
| Refactorability теряется | Правило «всё через DataProvider» + PHPStan + code review |
| Шаблон не покрывает кейс | Fail fast на Doc (Phase 1.3) — правим до Files/Stats/Audit |
| `bin/cli.php` разрастается | Только регистрация в registry; логика — в `src/Cli/Commands/`. Правило инфорцируется в `arch.md` |
