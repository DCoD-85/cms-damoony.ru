## 1. Wizard (HATEOAS State Machine) в AICLI

Цель: перевести генерацию с «один агент делает всё» на строгий пошаговый конвейер (State Machine) внутри `bin/aicli.php`.

**Архитектура Wizard:**
- **Жесткий State Machine:** Состояние стадии хранится в `var/wizard_session.json`. Агент не может перескочить стадию.
- **Strict Choices:** На каждой стадии `aicli` возвращает `next[]` с жестким списком разрешенных команд (например, только `page:new` или `page:write`).
- **Dry-Run (Фиктивный тест):** Перед переходом на финальную стадию «Done», CLI запускает проверку (например, `structure:check` или пробный запуск миграции БД). Агент получает ответ `ok: true/false` и только тогда завершает работу.
- **Rollback:** При провале стадии wizard инициирует откат созданных сущностей (через `*:remove --force`).

## 2. AI-Архитектор Баз Данных (DbCompiler)

Цель: научить AI проектировать структуру БД без использования сырого SQL.
- **JSON -> SQL:** AI передает безопасный JSON (описание таблиц, типов, связей).
- **DbCompiler (PHP):** Компилирует JSON в валидный SQL-файл миграции.
- **Валидация:** Проверка SQL на временной SQLite (dry-run) перед применением к боевой MariaDB через `db:migrate`.

## 3. damoonyengine.js (API & Интерактивность)

Цель: дать возможность генерировать динамические сайты без тяжелых SPA-фреймворков.
- **www/api.php:** Новый front controller для JSON API.
- **Damoony API:** Нативные JS-методы для отправки форм, фильтрации данных, toast-уведомлений.
- **Безопасность:** Строгая CSRF-защита, валидация и rate-limit для API-эндпоинтов.

## 4. Иерархическое планирование

Цель: генерация больших сайтов (50+ страниц) без переполнения контекста LLM.
- Разбиение Архитектора на уровни: Главный Архитектор (модули) -> Менеджеры модулей (списки страниц) -> Контент-воркеры.
