# 32_domain_dataprovider

## 1. Назначение

### 76_domain_dataprovider
Фасад домена damoony.ru и набор провайдеров для алиаса visuo. dataprovider (в корне домена) держит фасады всех алиасов с файлом dataprovider/dataprovider.php, автозагружает их в свойства по имени алиаса, устанавливает current по allias_accepted(). visuo\dataprovider — фасад visuo-провайдеров: user, doc, news, files, stats, audit. dataprovider_base — абстрактный класс с query(), открывает свою БД по localname из main_settings->domain_db[domain_real_name] или дефолт 'visuo_damoony'. dataprovider_user/doc/news/files/stats/audit — конкретные методы CRUD и запросов по своим таблицам.

## 4. Edge-cases

### 76_domain_dataprovider
- Корневой autoload: allias_dir не dir — return без обхода.
- autoload: файла dataprovider.php нет — continue.
- autoload: include_once false — error_file.
- autoload: class_exists($class) false — continue, свойство не заполняется.
- set_current: allias_accepted null или '' — return.
- set_current: isset($this->{$current}) false — return.
- dataprovider_base::__construct: domain_db не array или domain не найден — localname = 'visuo_damoony'.
- query: open(localname), затем query(sql, params) — единая точка.
- user::by_login: пустой результат — [].
- user::exists: SELECT 1 LIMIT 1, true если непусто.
- user::session_create: DATE_ADD(NOW(), INTERVAL ttl SECOND).
- user::session_find: token+expires_at>NOW() LIMIT 1.
- user::check_bruteforce: minutes clamp 1..1440, count неудач по login OR ip за период, fails < max = true.
- doc::sections_tree: only_published — WHERE status='published'.
- doc::article_by_slug: LEFT JOIN doc_sections, section_slug/section_title.
- doc::article_update: whitelist section_id/slug/title/excerpt/content_md/content_html/status; при пустом fields — return без записи.
- doc::search: MATCH ... AGAINST NATURAL LANGUAGE MODE.
- news::recent: limit clamp 1..100, только published по lang.
- news::slug_exists: exclude_id по id<>, иначе включает самого себя.
- news::create: filter_writable, пустой slug или title — 0.
- news::create: WRITABLE задаёт типы %s/%d для каждого поля.
- news::update: whitelist, empty data — return; иначе UPDATE с параметрами и id.
- news::publish: status='published', published_at COALESCE(published_at, NOW()).
- files::all_active: status='active', ORDER BY id ASC.
- files::create: slug/title/filename пусты — 0.
- files::set_status: не active/hidden — return без записи.
- files::increment_downloads: insert в file_downloads + UPDATE files downloads++ (два запроса).
- files::downloads_stats: days clamp 1..365.
- stats::top_articles: days+limit, WHERE status='published'.
- audit::log: payload_json null при пустом payload.
- audit::recent: LEFT JOIN users по login.
- audit::by_entity: WHERE entity_type AND entity_id.
- audit::by_user: WHERE user_id.

## 5. Скрытая логика

### 76_domain_dataprovider
Корневой dataprovider — реестр по алиасам. Его current — ярлык на провайдер текущего алиаса, что позволяет вызывать $main->dataprovider->current->… без уточнения алиаса. Провайдеры открывают свою БД на каждом query() через main->db->open(localname) — соединение может переключаться между запросами в разных алиасах. DB localname берётся из domain_db[domain_real_name], а не из доменного имени — это позволяет домену damoony.ru работать с базой visuo_damoony. dataprovider_news использует WRITABLE как whitelist одновременно для фильтрации полей и для подстановки placeholders — колонки не из WRITABLE молча игнорируются. files::create возвращает 0 при неполных данных, а files::set_status — no-op при неизвестном статусе. audit::log возвращает last_id, но в запросе использует ->insert_id() (побочный эффект) и затем $this->main->db->last_id() — двойной вызов, потенциально избыточный. user::session_create по умолчанию 30 дней. check_bruteforce считает неудачи по login OR ip, что блокирует IP даже при разных логинах.
