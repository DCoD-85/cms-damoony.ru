# 24_admin_views

## 1. Назначение

### 58_admin_views
Слой представления админки. Один общий layout _layout.php с header (nav, user), breadcrumbs, actions, tabs. Партиалы _domain_tabs, _allias_tabs, _context_nav. Шаблоны форм и списков по ресурсам: domain, allias, block, filler, page, media, scheme, stub, settings, security, resources, dashboard, login, result. Визуальные редакторы: page_visual (дерево JSON, drag/drop, undo/redo), scheme_edit (дерево схем, drag/drop, wireframe), page_code (редактор методов и JSON + live-preview iframe).

## 2. Контракт (Методы)

### 58_admin_views
Шаблоны — файлы верхнего уровня без классов. Точки входа: View::render('view', data) — include _layout.php, затем include view_file. Используют Csrf::field() для форм, WebRenderer::html(Result) для отображения результата, Paths/Config для скан-данных в allias_fillers и schemes_list.

## 3. Зависимости

### 58_admin_views
$_GET, $_POST, $_SESSION, Csrf, WebRenderer, Config, Paths, Result, PROJECT_ROOT/config/lang.config, $_SERVER['HTTP_HOST'].

## 4. Edge-cases

### 58_admin_views
- _layout: meta не передан — title null, breadcrumbs [], tabs [].
- _layout: tabs.show=1 и tabs.domain=1 — require _domain_tabs.
- _layout: tabs.show=1 и tabs.allias=1 — require _allias_tabs.
- _layout: $_SESSION['admin_ok'] непуст — показывается nav и кнопка Выйти.
- _layout: nav ссылки Domain/Stubs/Security/Settings, подсветка active по $p.
- _allias_tabs: активная вкладка по meta.tabs.active_allias, поле active_allias для БД читается из $active_allias (не из meta).
- _domain_tabs: active по meta.tabs.active_domain.
- _context_nav: необязательные $parent_link, $parent_title, $current_title; пустые — сегменты не рендерятся.
- allias_edit: $saved -> ok-msg, форма POST, switch available, select stub_current по $stubs, кнопка удаления с confirm.
- allias_fillers: Config instantiates локально; tab-полоса всех алиасов; switch toggle POST с value '0'/'1'.
- allias_list: row onclick window.location; toggle POST внутри ячейки с onclick event.stopPropagation; ссылка удаления с confirm.
- allias_new/domain_new: form с Csrf, поля name и domain, checkbox register.
- allias_remove/domain_remove: двухстадийное подтверждение — checkbox confirm_checked, input confirm_name; при несовпадении — errors.
- block_edit/filler_edit: два textarea (php и data), Csrf, кнопки сохранить и назад.
- block_new: name pattern [a-z][a-z0-9_]*, hidden domain.
- blocks_list: таблица блоков с has_php/has_data, кнопки ред/удалить/восстановить; ниже таблица layouts.
- dashboard: домены, switch toggle POST, allias-чипы (максимум 3 + '+N'), кнопка + и удалить с confirm.
- domain_edit: title, switch domain_available, select stub_current, datetime-local stub_until_date.
- filler_new: select allias и block, checkbox enable, скрытые ошибки если $alliases или $blocks пусты.
- login: Csrf, поля login/password, error.
- media_list: форма upload (multipart/form-data, hidden target_path и domain), список dirs и files, копирование URL через navigator.clipboard.
- page_code: вкладки logic/data, method-link список, генератор компонентов (table/form), редактор метода, iframe preview.
- page_edit: textarea available, checkbox auth, кнопка сохранить.
- page_new: select allias, name pattern, parent.
- page_visual: полный JS-движок VZ (undo/redo, addFromPalette, updateProps, save). Форма save-form POST json_code.
- pages_tree: рекурсивный render_page_node, кнопки page:toggle для auth/search/default, поиск по data-search.
- resource_edit: устаревший шаблон (использует $data, но контроллер передаёт $row), не используется — фактический рендер в resource_form.
- resource_form: поля по типам, relation select из $relations.
- resource_table: таблица rows, mb_strimwidth 50 для строк, relation resolve по id -> label.
- resources_list: кнопка sync, таблица ресурсов.
- result: WebRenderer::html, кнопка back_url.
- scheme_copy/new/remove/edit: формы с confirm_name/confirm, scheme_edit — drag/drop дерева, buildChildren -> finalData, fixReturn.
- security: tabs policy/users/logs, формы save_policy, reset_devices, create_invite (invite_type toggle), revoke_invite, таблица invites и logs.
- settings: select logic, connect_type, checkbox ui_ajax_forms.
- stub_edit: stub_title, stub_text.
- stubs_list: таблица stubs с полями id/title/html, POST на stubs:edit (карта AdminRouter: 'stubs' => 'StubController', action 'edit').
- scheme_edit form: submit собирает JSON из DOM, до отправки вызывает fixReturn.

## 5. Скрытая логика

### 58_admin_views
_layout использует base href="/admin/", поэтому относительные href и action в шаблонах работают от /admin/. Все формы POST содержат Csrf::field(). Переключения в списках (toggle) отправляются как скрытое поле value = '0' или '1' и checkbox onchange submit. Отображение Result унифицировано через WebRenderer::html. page_visual содержит полноценный клиентский движок VZ с JSON-состоянием {tag, class, children}, undo/redo ограничен 100 снимками, debounce для textarea 400 мс, hotkeys Ctrl+Z/Y/S, Delete удаляет выбранный узел. scheme_edit сериализует дерево через DOM на submit, добавляет поле return каждому узлу (true при наличии children, иначе false). page_code эмбедит iframe preview с указанием lang_default, for preview_url строится по allias и path. resource_edit фактически дублирует resource_form и обращается к $data, которая в контроллере отсутствует — при попадании на этот шаблон будет undefined variable warning.
