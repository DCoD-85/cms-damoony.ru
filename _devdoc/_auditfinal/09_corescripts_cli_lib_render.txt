# 09_corescripts_cli_lib_render

## 1. Назначение

### 22_corescripts_cli
CLI-точка входа для corescripts. Разрешает запуск только в PHP_SAPI=cli. Определяет константы CS_ROOT, CS_LIB, CS_CMD, CS_TPL, PROJECT_ROOT. Подключает базовые _lib. Разбирает argv: команда, ключи --key=value, флаги --flag, позиционные, -h. Формирует params, вызывает Class::run(params, Context), печатает через Renderer::cli, exit(0) при ok, exit(1) иначе.

### 23_corescripts_lib_core
Базовые библиотеки CLI. Cli — вывод и интерактив. Config — JSON-конфиг с точечными путями и array-key API, атомарная запись через Json, mutate под lock-файлом. Context — передача callback шагов. Paths — единая точка путей проекта и конфигов. Result — состояние выполнения (ok, steps, created, errors, warnings, summary). Fs — файловые операции с атомарной записью, rmrf, рекурсивный скан и копирование. Json — encode/decode/read/writeAtomic с табами вместо 4 пробелов.

### 24_corescripts_lib_render
Вывод и шаблоны. Renderer::cli формирует финальный отчёт Result в консоль. Template — рендер через плейсхолдеры <key>, скан .tpl, lint через php -l, render_str без чтения файла. Blocks — единый список блоков alliasglobal. ResourceManager — загрузка *.resource.php, генерация CREATE TABLE, sync с DESCRIBE и ALTER TABLE через DataGateway.

## 4. Edge-cases

### 22_corescripts_cli
- PHP_SAPI !== 'cli' — die('Only CLI mode allowed').
- command не задан — $command='help'.
- command='help' или отсутствует в $map — Cli::help(merge(['help'],keys)), exit(0).
- команда в $map, но файла нет — Cli::err('Command not implemented'), exit(1).
- -h — печать Usage и exit(0).
- Class::run бросил Throwable — Cli::err(message), exit(2).
- class_exists($class) false — Cli::err('Class not found'), exit(1).
- positional не пуст и params['name'] не задан — params['name']=positional[0].
- positional не пуст — params['positional']=positional всегда.

### 23_corescripts_lib_core
- Config::__construct: файл не найден — throw RuntimeException.
- Config::__construct: JSON не array — throw RuntimeException.
- Config::get/set/remove: точечная нотация, при отсутствии промежуточного ключа get возвращает default, set создаёт массив.
- Config::save: @copy в .bak, затем Json::writeAtomic.
- Config::mutate: fopen lock false — throw RuntimeException.
- Config::mutate: flock LOCK_EX false — throw RuntimeException.
- Config::mutate: fn бросил Throwable — flock LOCK_UN + fclose в finally, проброс.
- Fs::mkdir: mkdir false — throw RuntimeException.
- Fs::write: file_put_contents false — throw RuntimeException.
- Fs::writeAtomic: fopen false, flock false, короткая запись, rename false — throw RuntimeException с очисткой tmp.
- Fs::rmrf: путь не dir — @unlink файла или тихий выход.
- Fs::rel: путь не начинается с PROJECT_ROOT/' — возвращает путь без изменений.
- Fs::scan_recursive: dir не существует — [].
- Fs::copy_recursive: src не dir — mkdir dirname и @copy.
- Json::encode: json_encode false — throw RuntimeException.
- Json::decode: строка '' — default; json_decode null — default.
- Json::read: файл не найден или file_get_contents false — default.
- Json::writeAtomic: ошибки аналогичны Fs::writeAtomic.
- Paths::cfg: файл не найден или file_get_contents false или json_decode не array — [] (пустой конфиг).
- Paths::engineCfg: сначала engine.config, если нет — cms.config, иначе [].
- Paths::logic: engineCfg['logic'] пуст — 'alpha.0.0'.
- Paths::real: domains_real[domain] пуст — возвращает входной $domain.
- Paths::ns: domains_namespace[real] пуст — null.
- Paths::reset: сброс статических кэшей site_cfg и engine_cfg.

### 24_corescripts_lib_render
- Renderer::cli: r->ok — Cli::ok('Готово'), иначе Cli::err('Ошибка').
- Renderer::cli: r->created не пуст — список через Fs::rel.
- Renderer::cli: warnings не пуст — каждый через Cli::warn.
- Renderer::cli: errors не пуст — каждый через Cli::err; иначе при !ok и !empty(steps) — первый неудачный из реверса.
- Template::render: файл не найден — throw RuntimeException.
- Template::render: file_get_contents false — throw RuntimeException.
- Template::scan: dir не существует — [].
- Template::scan: только файлы с расширением .tpl.
- Template::lint: exec('php -l <file> 2>&1'), код 0 — null, иначе склейка вывода.
- Template::render_str: те же плейсхолдеры <key>, без проверки файла.
- Blocks::isBlock: строгое in_array.
- Blocks::forFiller: array_diff(LIST, SKIP).
- ResourceManager::load: файл не существует — throw RuntimeException.
- ResourceManager::getSqlType: неизвестный тип — VARCHAR(255).
- ResourceManager::generateCreateTableSQL: id -> INT AUTO_INCREMENT PRIMARY KEY, string -> VARCHAR(255), text -> TEXT, boolean -> TINYINT(1) DEFAULT 0, datetime -> DATETIME, integer -> INT, relation -> INT.
- ResourceManager::sync: resources_dir не dir — [].
- ResourceManager::sync: glob '*.resource.php', для каждого require, CREATE TABLE IF NOT EXISTS, DESCRIBE, ADD COLUMN для отсутствующих.
- ResourceManager::sync: Throwable на любом шаге — result['table'] с ok=false и message.

## 5. Скрытая логика

### 22_corescripts_cli
Карта команд связывает имя команды, файл и класс: domain:new, domain:list, domain:remove, allias:new, allias:list, allias:remove, page:new, block:new, filler:new, admin:passwd, settings:set, settings:list, page:toggle, allias:toggle, domain:toggle, filler:toggle, filler:remove, block:remove, vars:extract. Context получает callback, который печатает Cli::ok/Cli::err в момент вызова $ctx->step из команды, то есть шаги выполняются последовательно во время run. Renderer::cli формирует финальный отчёт. Код возврата: 0 ok, 1 неуспех, 2 исключение.

### 23_corescripts_lib_core
Json::encode применяет JSON_PRETTY_PRINT, затем preg_replace_callback по /^( +)/m переводит 4 пробела в табы через strlen/4. Json::writeAtomic и Fs::writeAtomic идентичны по схеме: tmp с random_bytes(4), fopen 'cb', flock LOCK_EX, fwrite, fflush, flock LOCK_UN, fclose, @rename, при любой ошибке @unlink(tmp) и throw. Config::mutate читает конфиг заново под lock, вызывает fn(cfg), сохраняет. Paths кэширует site_cfg и engine_cfg статически, сброс только через reset. Context хранит один callable и вызывает его из step. Result::error ставит ok=false и добавляет в errors, Result::step(false) тоже ставит ok=false. Paths::media строится по real(domain), а mediaRoot/shared — глобальные.

### 24_corescripts_lib_render
Renderer::cli выводит в начале пустую строку, статус ok/err, затем блоки created, warnings, errors. Логика последний неудачный шаг включается только когда errors пуст, но ok=false — это случай $ctx->step(...,false,...), не $r->error. Template::render_str и Template::render используют одинаковый плейсхолдер <key> и str_replace без экранирования. Blocks::LIST — источник правды для валидации имён блоков и для инициализации fillers в site.config (используется в командах AlliasNew, DomainNew). ResourceManager::sync идемпотентен: CREATE TABLE IF NOT EXISTS + ADD COLUMN только для отсутствующих колонок, счётчик добавленных возвращается в msg.
