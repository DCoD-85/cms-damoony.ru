# 17_www_tests_cases

## 1. Назначение

### 38_www_tests_cases_engine
Набор suites старого тест-раннера для движка: blacklist, language, messages, render, tree. Каждый файл возвращает array с title, setup, tests. Тесты используют Assert и заглушки main из lib/Stubs.

### 39_www_tests_cases_visuo
Suites старого тест-раннера для visuo: visuoattrs и подклассы (class, style, actions, data), visuoel-базовые и группы (button, form, form_fieldset, input, table), visuolink, visuolog, visuometa, visuorelease (включая visuorelease_settings), visuostruct (html/min/ajax), visuotag.

## 2. Контракт (Методы)

### 38_www_tests_cases_engine
Каждый cases/*.php возвращает array{title:string, setup:Closure, tests:array<string, Closure>}.

### 39_www_tests_cases_visuo
Каждый cases/*.php возвращает array{title:string, setup:Closure, tests:array<string, Closure>}. Тесты вызывают Assert::*, создают visuotag/visuoel/visuoattrs и проверяют release().

## 3. Зависимости

### 38_www_tests_cases_engine
SOURCES/blacklist.php, SOURCES/language.php, SOURCES/messages.php, SOURCES/render.php, SOURCES/tree.php, VISUO_SRC/visuotag.php, visuometa.php, visuolink.php, Assert, main, test_blacklist, fake_visuorelease.

### 39_www_tests_cases_visuo
visuo/sources/visuoattrs.php и подпапки, visuo/sources/visuotag.php, visuolink.php, visuometa.php, visuolog.php, visuorender.php, visuorelease_settings.php, visuopage.php, visuostruct.php, visuorelease.php, visuoels.php, Assert, main.

## 5. Скрытая логика

### 38_www_tests_cases_engine
В blacklist тестах используется test_blacklist extends blacklist с переопределением deny/allow — оригинальные методы завершали процесс через die. Тесты tree используют ReflectionMethod на приватный match — прямой вызов для проверки правил без запуска walk. render тест использует fake_visuorelease с полями calls[]. messages release проверяет HTML-содержимое через class иконки message_<status>. language setup не изолирует файлы — реальные inc из проекта language/, тест чувствителен к содержимому.

### 39_www_tests_cases_visuo
Тесты visuo не используют DB и filesystem — изолированы от окружения. В visuoattrs проверяется порядок атрибутов при release (class -> style -> actions -> id). В visuotag find поддерживает eq как позиционный индекс совпадения. structv создаёт тег 'struct' с классом cl_struct (без id) — это специальный структурный контейнер. data-атрибуты кодируются через visuoattrsdata::encode: строки без json -> простое значение, bool/int/array — JSON. XSS-проверки проверяют отсутствие literal '<script>' и наличие '&lt;script&gt;'.
