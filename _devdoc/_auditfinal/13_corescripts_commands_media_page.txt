# 13_corescripts_commands_media_page

## 1. Назначение

### 30_corescripts_commands_media
CLI-команды медиа. MediaDelete — удаление файла по basename в Paths::media(domain). MediaUpload — сохранение загруженного файла в dir, whitelist расширений, sanitize имени, защита от перезаписи суффиксом _<n>, для изображений (jpg/jpeg/png/gif/webp) ресайз до 1920px по ширине и принудительное сохранение в webp с качеством 80.

### 31_corescripts_commands_page
CLI-команды страниц. PageNew — создание algoritm_<ns>.php и algoritm_<ns>.data.json в дереве algoritm аллиаса, патч available в родительском .data.json, lint. PageToggle — переключение флага в дочернем .data.json (auth/search/default), чтение, merge с дефолтами, атомарная запись.

## 2. Контракт (Методы)

### 30_corescripts_commands_media
- MediaDelete: static run(array, ?Context=null): Result
- MediaUpload: static run(array, ?Context=null): Result

### 31_corescripts_commands_page
- PageNew: static plan(array): array, static run(array, ?Context=null): Result, private static patch_available_json(string file, string name): bool
- PageToggle: static plan(array): array, static run(array, ?Context=null): Result

## 3. Зависимости

### 30_corescripts_commands_media
Paths, Fs, getimagesize, imagecreatefrom{jpeg,png,gif,webp}, imagescale, imagedestroy, imagewebp, move_uploaded_file, pathinfo, preg_replace, basename, UPLOAD_ERR_OK.

### 31_corescripts_commands_page
Validate, Paths, Fs, Template, Json, Result, Context, CS_TPL/page/page.php.tpl, CS_TPL/page/page.data.json.tpl.

## 4. Edge-cases

### 30_corescripts_commands_media
- MediaDelete: domain или file пуст — r->error('Неверные параметры'), return.
- MediaDelete: basename применяется к file как защита от ../.
- MediaDelete: файл не is_file — r->error('Файл не найден').
- MediaDelete: файл удалён — r->step('Файл удален', true, file).
- MediaUpload: dir пуст — r->error('Папка назначения не указана'), return.
- MediaUpload: file null или file['error']!==UPLOAD_ERR_OK — r->error('Ошибка загрузки файла'), return.
- MediaUpload: ext не в allowed [jpg,jpeg,png,gif,webp,svg,pdf,zip,css,js,ico,woff2,woff,ttf,mp4,mp3,doc,docx,xls,xlsx] — r->error('Недопустимое расширение' + список), return.
- MediaUpload: имя sanitize preg_replace('[^a-zA-Z0-9_\-\.]','_', basename(name)).
- MediaUpload: dest существует — цикл while is_file, dest = <base>_<i>.<ext>, i++ (без верхней границы).
- MediaUpload: изображение, getimagesize вернул false — move_uploaded_file в dest (без webp).
- MediaUpload: изображение, imagecreatefrom* вернул false — move_uploaded_file в dest (без webp).
- MediaUpload: изображение, width>1920 — newHeight = floor(height*(1920/width)), imagescale(1920,newHeight).
- MediaUpload: после ресайза dest меняется на <dirname>/<filename>.webp (принудительно, независимо от исходного ext).
- MediaUpload: function_exists('imagewebp') false — move_uploaded_file в уже переименованный .webp-путь (фактическое расширение сохраняется от move).
- MediaUpload: не-изображения и svg/pdf/zip/css/js/ico/woff/ttf/mp4/mp3/doc/xls — move_uploaded_file без изменений.

### 31_corescripts_commands_page
- PageNew: Validate allias_name(name) вернул строку — r->step(false), return.
- PageNew: Validate domain или allias_name(allias) вернул строку — r->step(false), return.
- PageNew: Paths::allias не dir — r->error('Аллиас не найден'), return.
- PageNew: Validate::page_path(parent) вернул строку — r->error('Некорректный путь родителя'), return.
- PageNew: Paths::ns null — r->error('Не найден domains_namespace'), return.
- PageNew: !is_dir(parent_dir) — r->error('Родительский каталог не найден'), return (до записи).
- PageNew: !is_file(parent_file) — r->error('Родительский алгоритм не найден'), return (до записи).
- PageNew: Fs::exists(page_file) — r->error('Страница уже существует'), return.
- PageNew: шаблоны php/json не найдены — r->error('Шаблоны не найдены'), return.
- PageNew: parent_json существует и Json::read не array — r->error('Родительский .data.json битый'), return.
- PageNew: parent_json не существует — r->warn('Родительский .data.json не найден'), available не патчится.
- PageNew: patch_available_json вернул false — r->warn("'{name}' уже в $available") или тихо (нет ключа available — то же false, без предупреждения).
- PageNew: lint вернул ошибку — r->warn('Lint: rel: err').
- PageToggle: Validate domain/allias/page_path вернул строку — r->step(false), return.
- PageToggle: key не в ['auth','search','default'] — r->step(false, 'недопустимый ключ'), return.
- PageToggle: php_file не найден — r->error('Страница не найдена'), return.
- PageToggle: json_file не array или default не array — merge не выполняется, дефолты сохраняются.
- PageToggle: value==='0' — false, иначе true.
- PageToggle: Json::writeAtomic бросил Throwable — r->error('Не сохранить').

## 5. Скрытая логика

### 30_corescripts_commands_media
MediaDelete не проверяет наличие домена, путь строится как Paths::media(domain).'/'.basename(file), то есть у пользователя нет доступа выше media/<real>/, но через относительные сегменты в basename защита срабатывает: basename('../../a') = 'a'. MediaUpload whitelist не включает php, что исключает загрузку исполняемых файлов, но svg остаётся в списке (XSS-риск на отдаче без заголовков). При ресайзе width>1920 сначала imagescale, imagedestroy старого, затем принудительное переименование в .webp и imagewebp с качеством 80; фактическое имя файла на диске может быть <base>.webp или <base>_<n>.webp при коллизии. Fallback move_uploaded_file(file['tmp_name'], dest) с dest = ....webp копирует исходный jpeg/png с расширением .webp — на диске получится несоответствие mime и расширения. Fs::mkdir(dir) вызывается до sanitize, поэтому несуществующая папка создаётся до попыток записи.

### 31_corescripts_commands_page
PageNew собирает имя класса algoritm_<parent_ns>_<name> и путь parent_dir/name. Проверки родителя и шаблонов выполняются до первой записи, чтобы не оставить сироту (комментарий в коде). Json::writeAtomic используется для parent_json. PageToggle дефолт: available=[''], auth=false, search=true, default=false; merge с текущим — array_merge($default, $cur['default']), текущее перекрывает дефолт. patch_available_json требует наличия data['default']['available'] как array и отсутствия $name в нём; возвращает false без предупреждения при отсутствии ключа available.
