# 29_visuoel_form_table_tabs

## 1. Назначение

### 66_visuoel_form
Группа form. visuoel_form — singleton-группа (singleton=true): один form_form на группу. Обёртка div.blockform. form() возвращает единственный form_form, повторный вызов возвращает тот же объект. visuoel_form_form — элемент form с action/name/method/enctype, data-form-jquery, data-load, опциональным div.form_title и div.form_body (vt_end — слот для детей). visuoel_form_fieldset — fieldset с legend внутри form_body.

### 70_visuoel_table
Таблица/сетка. visuoel_table — группа таблицы (singleton=false). Два режима: divный (по умолчанию) — div.visuotable с div.ttype.tbody/row/col.cols_N; html_mode — настоящая <table> с <thead>/<tbody>/<tfoot>/<tr>/<td>. Секции visuoel_table_section с zone ('thead'|'tbody'|'tfoot'). Строки visuoel_table_row. Ячейки visuoel_table_cell с width/colspan/rowspan/inline/class/content и content_block (visuoel_field_block).

### 71_visuo_el_tabs
Группа вкладок. visuoel_tabs — multi-группа (singleton=false), контейнер div.tabs с div.hhead и div.bbody. visuoel_tabs_page — страница вкладки: span.tab_title с data-tab-target и data-action=tabs-show плюс div.tab_page с id=tab_<spl_object_id>. init() переопределён: сначала build(), затем для каждой страницы page->init(), первая получает class ' selected' на title и page, титулы уходят в vt_head, тела — в vt_body.

## 4. Edge-cases

### 66_visuoel_form
- visuoel_form::form: singleton=true и visuoel_form_form уже установлен — возврат существующего, elements=[el] уже.
- visuoel_form::form: первый вызов — создаётся, сохраняется в свойстве, elements=[el].
- visuoel_form_form::build: action/name/method/enctype добавляются только при непустом значении ($v = ... проверка).
- visuoel_form_form::build: form_jquery=true — data-form-jquery=true.
- visuoel_form_form::build: form_data_jquery непуст — data-load=<значение>.
- visuoel_form_form::build: title_text непуст — div.form_title с содержимым (esc).
- visuoel_form_form::build: form_class непуст — attrs_class_add.
- visuoel_form_form__data::set: method 'get' — enctype='get/html'.
- set: method 'post' — enctype='application/x-www-form-urlencoded'.
- set: method 'file' — form_method='POST' и enctype='multipart/form-data'.
- set: method иной — form_enctype = переданный (или дефолт).
- visuoel_form_fieldset::build: legend непуст — tag legend с esc содержимым и parent обратно.
- visuoel_form_fieldset::build: legend пуст — legend не рисуется (тест 'legend пустой — не рисуется').
- fieldset внутри form_form: добавляется через form->fieldset(), элементы в elements form_form, рендер вставляется в vt_end (form_body).

### 70_visuoel_table
- visuoel_table::build: html_mode=true — tag('table', class='visuotable_html'), вставка html_attrs.
- build: html_mode=false — tag('div', class='visuotable').
- head/body/foot: singleton-секция, при повторном вызове возврат существующей, elements не растёт.
- row(): shortcut -> body()->row().
- visuoel_table_section::build: html_mode — tag(zone); иначе tag('div', class='ttype <zone>').
- row(): создаёт visuoel_table_row и добавляет в elements.
- visuoel_table_row::build: html_mode — <tr>; иначе <div class='row'>.
- cell(width, colspan, rowspan, inline): устанавливает значения и добавляет в elements.
- visuoel_table_cell::build html_mode: td; colspan/rowspan добавляются при >1; width в style='width: N%;'.
- build html_mode: content непуст — is_html ? raw : htmlspecialchars(ENT_QUOTES).
- build html_mode: width>0 — attrs_style_add 'width: N%;'.
- build divный: class = 'col' + ' cols_<width>' (если width>0) + ' <extra>' (если class) + ' colelsinline' (если inline).
- build divный: vt_end = div.col_block (внутри div.col-inside), куда пришиваются дети.
- ensure_content_block: content==='' — ничего; иначе при content_block===null создаётся visuoel_field_block и добавляется в элементы.
- ensure_content_block: content/is_html передаются в bdata content и is_html (порядок рендера = порядок вызовов add/set/html).
- set: data->set(text) -> is_html=false, ensure_content_block.
- html: data->html(html) -> is_html=true, ensure_content_block.
- detect_html_mode: проход по parent до visuoel_table__data — определяет режим по ближайшей таблице.
- data->set и data->add / data->html: content_block перезаписывается при повторном вызове.

### 71_visuo_el_tabs
- init: повторный вызов — return по флагу $this->init.
- init: элементы не visuoel_tabs_page — пропускаются (continue).
- init: страница без title (vt_title null) — title не добавляется в hhead, класс selected не ставится, но страница всё равно рендерится в bbody.
- page: переданный $__data не visuoel_tabs_page__data — создаётся дефолт.
- build: vt_end = bbody, дети пришиваются в bbody.
- visuoel_tabs_page::build: id = 'tab_' . spl_object_id($this).
- build: title -> data-tab-target=id, data-action=tabs-show; содержимое = esc(title) при непустом.
- build: page -> div.tab_page id=id, vt_end=page (дети внутри страницы).

## 5. Скрытая логика

### 66_visuoel_form
visuoel_form — singleton-группа: form() при повторном вызове возвращает тот же visuoel_form_form, но elements перезаписывается каждый раз ([$el]). Это значит, что после form() добавление fieldset идёт через form->fieldset() или form->add(), а не через visuoel_form->elements напрямую. visuoel_form_form__data::set — ключевая точка: 'file' превращается в POST+multipart (это то, что старые тесты проверяют как 'data->set(file) -> POST + multipart'); 'get' — в 'get/html'; иначе enctype берётся как переданный. vt_start = <form>, vt_end = <div class=form_body> — дети form_form рендерятся внутри form_body. form_jquery и form_data_jquery — маркеры для клиентского AJAX-перехвата; form_data_jquery по умолчанию ['on'=>true,'layerto'=>'dt_center'].

### 70_visuoel_table
visuoel_table — ключевой элемент для двух режимов рендера, режим определяется динамически через detect_html_mode() подъёмом по parent до ближайшей visuoel_table__data, поэтому режим задаётся на таблице один раз и применяется ко всем вложенным section/row/cell. В divном режиме скелет фиксированный: div.visuotable > div.ttype.tbody > div.row > div.col.cols_N > div.col-inside > div.col_block. В html_mode — настоящая таблица с <thead>/<tbody>/<tfoot>/<tr>/<td>, colspan/rowspan через атрибуты, width через style. visuoel_table_cell сам строит только скелет; при set/html создаёт внутри visuoel_field_block (content_block) — это единый механизм для голого текста, что позволяет ячейке унаследовать обёртку field-стиля. Порядок рендера в ячейке — порядок вызовов add/set/html: если set() вызван первым, content_block окажется в elements раньше добавленных через add(). Секции head/body/foot — singleton, строки в них добавляются многократно через row(). detect_html_mode() кэша нет, каждый узел при build проходит parent-цепочку до таблицы.

### 71_visuo_el_tabs
init() переопределяет базовый init и вызывает build() до обхода элементов — без этого vt_head/vt_body были бы null. Первая валидная страница помечается selected на двух узлах: tab_title и tab_page — это единственное место, где устанавливается начальный активный таб. Порядок элементов страницы соответствует порядку вызовов page(). data-tab-target работает совместно с JS в старых представлениях: onclick по [data-action=tabs-show] переключает классы selected. spl_object_id стабилен в рамках одного процесса, но разный между запросами — при AJAX-рендере id будет отличаться.
