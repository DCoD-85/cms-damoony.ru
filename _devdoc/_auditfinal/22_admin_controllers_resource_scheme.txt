# 22_admin_controllers_resource_scheme

## 1. Назначение

### 53_admin_controllers_resource
Контроллер ресурсов данных админки. index — список *.resource.php в allias/{allias}/resources. sync — вызов ResourceManager::sync. edit — таблица записей по ресурсу, подгрузка relation-справочников. form — форма создания/редактирования записи с типизацией полей, DataGateway insert/update.

### 54_admin_controllers_scheme
Контроллер схем alliasscheme. list — список схем домена. copy — копирование схемы с заменой имён, патч alliasscheme.php. remove — удаление схемы и её записи в alliasscheme.php. new — создание схемы из исходной. edit — редактирование схемы, JSON -> .data.php через var_export.

## 2. Контракт (Методы)

### 53_admin_controllers_resource
ResourceController: index(), sync(), edit(), form()

### 54_admin_controllers_scheme
SchemeController: list(), copy(), remove(), new(), edit()

## 3. Зависимости

### 53_admin_controllers_resource
ResourceManager, DataGateway, PROJECT_ROOT/app/alpha.0.0/domain/{domain}/allias/{allias}/resources, $_GET, $_POST, AuditLog.

### 54_admin_controllers_scheme
Paths, Config, Fs::writeAtomic, $_GET, $_POST, glob, is_file, str_ends_with.

## 4. Edge-cases

### 53_admin_controllers_resource
- index: resources_dir не dir — resources=[].
- index: glob '*.resource.php' пуст — resources=[].
- index: при require файла ресурса res не array — PHP warning, дальше падение на $res['id'].
- index: id в ресурсе = basename без '.resource.php'.
- sync: requirePost; пути ресурсов формируются из get('domain') и get('allias'), не post.
- sync: ResourceManager::sync, synced и errors считаются по results.
- sync: redirect resources с synced и errors в query.
- edit: resource_file не существует — redirect resources.
- edit: require файла ресурса; table = resource['table'].
- edit: rows = SELECT * FROM table ORDER BY id DESC LIMIT 100.
- edit: relation — SELECT id, display AS label FROM field['table'].
- edit: render resource_table с meta.title = resource['title'].
- form: resource_file не существует — redirect resources.
- form: id>0, find null — redirect resource:edit.
- form: relation — SELECT id, display AS label FROM field['table'].
- form POST: пропускаются id и created_at.
- form POST: boolean — !empty -> 1 иначе 0.
- form POST: integer/relation — непусто -> (int), пусто -> null.
- form POST: остальное — (string).
- form POST: id>0 — update, иначе insert; при наличии поля created_at — date('Y-m-d H:i:s').
- form POST: redirect resource:edit.

### 54_admin_controllers_scheme
- list: domain пуст — redirect dashboard.
- list: dir не существует — schemes=[].
- list: пропуск *.data.php.
- copy POST: target пуст или regex не '^[a-z][a-z0-9_]*$' — render result 'Некорректное имя схемы'.
- copy POST: src_php или src_data отсутствует — редирект не выполняется (нет else), render scheme_copy.
- copy POST: c_php с заменой 'class alliasscheme_<source>' -> 'class alliasscheme_<target>' и '<source>.data.php' -> '<target>.data.php'.
- copy POST: main_file alliasscheme.php — добавление property, include и new только при отсутствии target в файле.
- copy POST: redirect schemes:list&copied=1.
- remove: scheme 'www','visuo','error' — die('Базовые схемы удалять нельзя').
- remove POST: confirm === scheme — @unlink php и data, удаление строк с prop в alliasscheme.php, redirect removed=1.
- remove POST: confirm !== scheme — падение на render scheme_remove.
- new POST: target некорректен — errors.
- new POST: src отсутствует или dst есть — errors 'Исходная схема не найдена или такая уже существует'.
- new POST: успешно — writeAtomic и патч alliasscheme.php, redirect saved=1.
- edit: file_data нет — render result 'Файл схемы не найден' с meta.
- edit POST: json_decode вернул array — php_code через var_export, writeAtomic; json_decode null — запись не происходит.
- edit POST: redirect saved=1 безусловно.
- edit: schemes список сортируется sort.

## 5. Скрытая логика

### 53_admin_controllers_resource
Путь ресурсов жёстко содержит alpha.0.0 и не использует Paths::logic(). sync берёт domain/allias из GET, хотя форма в resources_list отправляет POST — редирект после sync работает, но параметры в URL формируются из GET. form отправляет POST на тот же URL, но action пустой — форма отправляется по текущему URL. Тип relation в insert сохраняет null при пустом значении, а не 0. created_at ставится только при insert и только если поле объявлено в ресурсе. DataGateway::connect кэширует PDO, поэтому несколько ресурсов в одном запросе используют одно соединение и один localname (первый подходящий), не свой per-resource.

### 54_admin_controllers_scheme
remove проверяет scheme на три базовых до POST — die() вылетает без рендера, даже если форма не отправлялась. copy и new используют разный порядок вставки include в патче (в new include вставляется до исходного, в copy — после), итог зависит от порядка, но обе версии работают за счёт отсутствия target в файле. edit восстанавливает данные из .data.php через require — если файл вернёт не array, поведение не определено, но запись потом делает var_export для JSON-структуры. copy при отсутствии исходной схемы молча не редиректит и рендерит форму — без сообщения пользователю.
