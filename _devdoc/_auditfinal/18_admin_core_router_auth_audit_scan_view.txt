# 18_admin_core_router_auth_audit_scan_view

## 1. Назначение

### 41_admin_router
Маршрутизатор админки. Статическая карта resource => Controller, разбор p по ':' на resource и action, подключение BaseController и файла контроллера, инстанцирование, вызов action(). Возвращает bool — false при отсутствии ресурса, файла, класса или метода.

### 42_admin_auth_security
Аутентификация и безопасность админки. Auth — login/logout/check, brute-force по IP через secure/admin_fails.json, задержки после 3 неудач и бан 900 секунд после 5. Csrf — токен в $_SESSION['csrf'], hidden-поле, проверка hash_equals. Security — fingerprint-устройства, приглашения, привязка устройств, whitelist IP, атомарная запись admins.config и security.log.

### 43_admin_audit
Журнал действий админки. AuditLog пишет JSON-строки в secure/logs/admin.log с ротацией по 10 MB. Хелперы login_ok/login_fail/logout/action_ok/action_fail.

### 44_admin_scan
Сканеры доступных значений для форм админки. Список тем домена, движков, connect_types. Дерево страниц аллиаса с метаданными из .rules.json. Блоки домена — по папкам alliasglobal/* + по схемам alliasscheme_*.data.php. Детали блоков, филлеры аллиаса.

### 45_admin_view
View — рендер view-шаблона через _layout.php с извлечением переменных и дефолтной мета (title, breadcrumbs, actions, tabs). WebRenderer — HTML-блок Result со статусом, шагами, созданными файлами, предупреждениями, ошибками.

## 4. Edge-cases

### 41_admin_router
- dispatch: resource не в карте — false.
- dispatch: BaseController.php отсутствует — require пропускается.
- dispatch: файл контроллера не существует — false.
- dispatch: класс не существует после require — false.
- dispatch: метод не существует на контроллере — false.
- dispatch: action по умолчанию 'index' если ':' не указан.
- dispatch: p='domain:new' — resource=domain, action=new.
- dispatch: p='blocks' — resource=blocks, action=index (в карте BlockController::index отсутствует — false).

### 42_admin_auth_security
- Auth::__construct: admin.config отсутствует или битый — login='admin', hash=''.
- Auth::login: is_banned(ip) — delay(DELAY_USEC), return false.
- Auth::login: hash==='' — record_fail, return false.
- Auth::login: !ok и fails_count>=3 — дополнительный delay 500ms.
- Auth::login: ok — reset_fails, session_regenerate_id, admin_ok=true, admin_login.
- Auth::login: ok не устанавливает admin_role (в отличие от invite).
- Auth::logout: setcookie с time()-42000 (похоже опечатка вместо -42000 при expires).
- Auth::record_fail: count>=5 — banned_until=time()+900.
- Auth::record_fail: чистка записей старше 7 дней.
- Csrf::token: отсутствие в $_SESSION — генерирует 32 байта hex.
- Csrf::check: POST['_csrf'] пуст или hash_equals false — false.
- Security::cfg: admin.security.config отсутствует — дефолт whitelist + require_fingerprint.
- Security::admins: admins.config отсутствует — users=[], invites=[].
- Security::write_atomic: Fs загружен — Fs::writeAtomic, иначе вручную через tmp+flock+rename.
- Security::is_whitelisted: mode blacklist — всегда true; whitelist — IP в ip_whitelist или loopback.
- Security::find_device: canvas пуст — null. Совпадение: >=2 из 3 хэшей и canvas обязателен.
- Security::touch_device: устройство уже видно <300 сек — return без записи; иначе обновление.
- Security::add_device: пользователь не найден — throw RuntimeException.
- Security::reset_user_devices: guard_login === login — log и false (нельзя сбросить свои).
- Security::create_invite: role='bind_only' без target_user — throw RuntimeException; target_user не найден — throw.
- Security::validate_invite: used или expires_at<time() — null; bind_only с отсутствующим target — null.
- Security::create_user_from_invite: логин уже существует — false; в остальных случаях записывает password_hash и первое устройство, помечает invite used.
- Security::bind_device_from_invite: не bind_only или password_verify false — false.

### 43_admin_audit
- write: каталог отсутствует — @mkdir 0755.
- write: файл больше 10 MB — rename в admin.log.YmdHis.
- write: json_encode false — return без записи.
- write: file_put_contents false — молча, без ошибки.
- write: user из $_SESSION['admin_login'] или '?'.
- write: ua обрезается до 200 символов.

### 44_admin_scan
- skinsFor: skins_dir не dir — [].
- logics: app/<name>/domain не dir — пропуск.
- pageTree: base не dir — [].
- pageTree: algoritm.php не файл — [].
- pageNode: <cls>.php отсутствует — has_file false, meta дефолт.
- parseMeta: .rules.json не array — дефолт (available=[], auth=false, search=false, default=false).
- blocksFor: dir не dir — [].
- blocksFor: имя в Blocks::SKIP (script) — пропуск.
- blocksFromSchemes: обход всех *.data.php в alliasscheme, поиск nodes с class начинающимся на dt_, кроме dt_script.
- layoutsFor: type==='layout' — добавить class.
- blocksDetailsFor: union blocksFor + blocksFromSchemes + Blocks::LIST, минус middle, sort, для каждого has_php и has_data.
- fillersFor: fillers_cfg = getKeys(['fillers', real, allias]) -> block=>bool. Для каждого блока has_base (block/block.php), has_filler (block/block_<allias>.php), enabled.

### 45_admin_view
- View::render: файл view не найден — http_response_code(500), echo 'View not found', return.
- View::render: meta не передан — дефолт {title:null, breadcrumbs:[], actions:'', tabs:[]}.
- View::render: extract с EXTR_SKIP — конфликты не перетирают уже имеющиеся переменные.
- WebRenderer::html: r->ok — '✓ Готово', иначе '✗ Ошибка'.
- WebRenderer::html: steps — class ok/err по s->ok.
- WebRenderer::html: msg в шаге — ' — '+htmlspecialchars.
- WebRenderer::html: created — список через Fs::rel.
- WebRenderer::html: warnings, errors — списки.
- WebRenderer::html: пустые секции не печатаются.

## 5. Скрытая логика

### 41_admin_router
Карта алиасов: dashboard, domain, allias, filler, block/blocks, page/pages, media, settings/db, scheme/schemes, stub/stubs, security, resource/resources. resource 'settings' и 'db' ведут на SettingsController, 'blocks' и 'block' — на BlockController (у BlockController нет метода index), 'pages' и 'page' — на PageController, 'schemes'/'scheme' — на SchemeController, 'stubs'/'stub' — на StubController, 'resource'/'resources' — на ResourceController. Автозагрузка константы CS_* не делает — предполагает bootstrap уже загрузил _lib.

### 42_admin_auth_security
Auth использует отдельные настройки brute-force: MAX_FAILS=5, BAN_SECONDS=900, DELAY_AFTER=3, DELAY_USEC=500000. login сравнивает логин через hash_equals, а пароль через password_verify. Auth не сохраняет роль в $_SESSION при обычном login (только admin_role при autologin/invite). Security::log пишет JSON-строки в secure/logs/security.log через FILE_APPEND|LOCK_EX. Приглашение имеет ttl по умолчанию 86400 (сутки). Fingerprint сравнивает canvas/webgl/system; для успеха нужен canvas и хотя бы ещё один. Security::touch_device устанавливает unset($d) при попытке вернуть по ссылке — обходной приём для раннего выхода из foreach.

### 43_admin_audit
Формат записи: ts, ip, ua, user, act, ok, data. Все хелперы делегируют в write, кроме login_fail/action_fail с ok=false. Ротация — rename с суффиксом времени, без сжатия и без ограничения числа файлов. Запись через FILE_APPEND|LOCK_EX. Молчаливый отказ при ошибке записи, никакой обратной связи.

### 44_admin_scan
pageTree корневой узел — algoritm с meta из algoritm.php, дочерние — обход всех подпапок базового каталога. class строится как 'algoritm_<path>'. usort по name. parseMeta игнорирует search и default (всегда false), хотя в .rules.json они могут быть. blocksFor использует только фактическое содержимое alliasglobal; blocksFromSchemes дополняет по class dt_* из схем. В blocksDetailsFor явно исключается 'middle', в fillersFor — только блоки, не равные 'script' и не 'middle'. connectTypes — хардкод ['http://','https://'].

### 45_admin_view
View не делает ob_start, не ставит заголовки — предполагается, что bootstrap уже сделал. Meta всегда массив, даже если шаблон не передал его — упрощает шаблон. WebRenderer не перехватывает исключения — если Fs::rel бросит, страница упадёт. HTML строится конкатенацией, все пользовательские значения экранируются htmlspecialchars.
