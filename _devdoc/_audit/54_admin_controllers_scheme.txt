1. Назначение
Контроллер схем alliasscheme. list — список схем домена. copy — копирование схемы с заменой имён, патч alliasscheme.php. remove — удаление схемы и её записи в alliasscheme.php. new — создание схемы из исходной. edit — редактирование схемы, JSON → .data.php через var_export.

2. Контракт (Методы)
SchemeController: list(), copy(), remove(), new(), edit()

3. Зависимости
Paths, Config, Fs::writeAtomic, $_GET, $_POST, glob, is_file, str_ends_with.

4. Edge-cases
- list: domain пуст — redirect dashboard.
- list: dir не существует — schemes=[].
- list: пропуск *.data.php.
- copy POST: target пуст или regex не '^[a-z][a-z0-9_]*$' — render result 'Некорректное имя схемы'.
- copy POST: src_php или src_data отсутствует — редирект не выполняется (нет else), render scheme_copy.
- copy POST: c_php с заменой 'class alliasscheme_<source>' → 'class alliasscheme_<target>' и '<source>.data.php' → '<target>.data.php'.
- copy POST: main_file alliasscheme.php — добавление property, include и new только при отсутствии target в файле.
- copy POST: redirect schemes:list&copied=1.
- remove: scheme 'www','visuo','error' — die('Базовые схемы удалять нельзя').
- remove POST: confirm === scheme — @unlink php и data, удаление строк с prop в alliasscheme.php, redirect removed=1.
- remove POST: confirm !== scheme — падение на render scheme_remove.
- new POST: target некорректен — errors.
- new POST: src отсутствует или dst есть — errors 'Исходная схема не найдена или такая уже существует'.
- new POST: успешно — writeAtomic и патч alliasscheme.php, redirect saved=1.
- edit: file_data нет — render result 'Файл схемы не найден' с meta.
- edit POST: json_decode вернул array — php_code через var_export, writeAtomic; json_decode null — запись не происходит.
- edit POST: redirect saved=1 безусловно.
- edit: schemes список сортируется sort.

5. Скрытая логика
remove проверяет scheme на три базовых до POST — die() вылетает без рендера, даже если форма не отправлялась. copy и new используют разный порядок вставки include в патче (в new include вставляется до исходного, в copy — после), итог зависит от порядка, но обе версии работают за счёт отсутствия target в файле. edit восстанавливает данные из .data.php через require — если файл вернёт не array, поведение не определено, но запись потом делает var_export для JSON-структуры. copy при отсутствии исходной схемы молча не редиректит и рендерит форму — без сообщения пользователю.
