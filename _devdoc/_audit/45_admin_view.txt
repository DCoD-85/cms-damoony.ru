1. Назначение
View — рендер view-шаблона через _layout.php с извлечением переменных и дефолтной мета (title, breadcrumbs, actions, tabs). WebRenderer — HTML-блок Result со статусом, шагами, созданными файлами, предупреждениями, ошибками.

2. Контракт (Методы)
View: static render(string view, array data=[]): void
WebRenderer: static html(Result $r): string

3. Зависимости
ADMIN_ROOT/views/_layout.php, ADMIN_ROOT/views/<view>.php, Result, Fs.

4. Edge-cases
- View::render: файл view не найден — http_response_code(500), echo 'View not found', return.
- View::render: meta не передан — дефолт {title:null, breadcrumbs:[], actions:'', tabs:[]}.
- View::render: extract с EXTR_SKIP — конфликты не перетирают уже имеющиеся переменные.
- WebRenderer::html: r->ok — '✓ Готово', иначе '✗ Ошибка'.
- WebRenderer::html: steps — class ok/err по s->ok.
- WebRenderer::html: msg в шаге — ' — '+htmlspecialchars.
- WebRenderer::html: created — список через Fs::rel.
- WebRenderer::html: warnings, errors — списки.
- WebRenderer::html: пустые секции не печатаются.

5. Скрытая логика
View не делает ob_start, не ставит заголовки — предполагается, что bootstrap уже сделал. Meta всегда массив, даже если шаблон не передал его — упрощает шаблон. WebRenderer не перехватывает исключения — если Fs::rel бросит, страница упадёт. HTML строится конкатенацией, все пользовательские значения экранируются htmlspecialchars.
