1. Назначение
Контроллер филлеров админки. new — форма и FillerNew с опциональным enable в site.config. edit — редактор php и data через Fs::writeAtomic. toggle — FillerToggle. remove — FillerRemove.

2. Контракт (Методы)
FillerController: new(), edit(), toggle(), remove()

3. Зависимости
Config, Paths, Fs, Result, CS_CMD/{FillerNew,FillerToggle,FillerRemove}.php, ADMIN_ROOT/_lib/Scan.php, AuditLog, PROJECT_ROOT/config/site.config.

4. Edge-cases
- new: domain из GET или POST; allias из GET или POST; block из GET.
- new: domain пуст — redirect dashboard.
- new: getKeys(['domains_real',domain]) null — redirect dashboard.
- new: alliases и blocks собираются из Config и Scan.
- new POST: block_path/filler_php уже есть — result step 'Filler уже существует', FillerNew не вызывается.
- new POST: !exists — FillerNew::run(name=allias, block, domain, allias).
- new POST: result->ok и enable — Config::mutate setKeys fillers[real][allias][block]=true (если ещё не true), AuditLog::action_ok.
- new POST: Config::mutate бросил — result->warn, без error.
- edit: php_f не файл — redirect allias:fillers.
- edit POST: Fs::writeAtomic php и data, redirect filler:edit&saved=1.
- edit: data_f не существует — дефолт "<?PHP\nreturn [\n\t\n];\n".
- toggle: requirePost, FillerToggle::run, AuditLog::action_ok, redirect allias:fillers.
- remove: requirePost, FillerRemove::run, AuditLog::action_ok, redirect allias:fillers.

5. Скрытая логика
new использует get() ?: post() для domain и allias — при пустом GET берётся POST, при непустом — GET приоритетнее. Result импортируется из _lib, создаётся новый при 'Filler уже существует' без вызова FillerNew — это упрощает повторный клик. enable устанавливается только если result->ok, но не проверяет существующий true — hasKeys не проверяется, setKeys перезапишет true на true (безвредно). edit/toggle/remove не проверяют домен/алиас/блок через Config, полагаются на валидность из URL. requirePost отсутствует в new/edit (GET-форма) и включён в toggle/remove.
